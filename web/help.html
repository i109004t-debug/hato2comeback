HT2の使い方

管理者から届いた運営画面のURLと、自分専用のアカウントでログインします。スタッフがAWSと契約したり、AWSに登録したりする必要はありません。

初めてログインしたときは、パスワードを変更し、スマートフォンの認証アプリを登録してください。

組織の問い合わせ先、送れる件数の上限、詳しい手順は、導入担当者から配られた「利用者操作手順書」に書いてあります。ログインできないときや、認証アプリを入れた端末をなくしたときは、管理者に連絡してください。

配信する

  1. 「配信」で配信リスト、件名、本文を入力し、「下書き保存」を押します。
  2. 「プレビュー」と「テスト送信」で確かめます。テスト送信は、設定で登録した最大5件だけに送られます。
  3. 「承認申請」を押し、承認者に配信IDを伝えます。申請した本人は承認できません。
  4. 承認者は「配信履歴」から配信を開き、固定された内容を確かめて「承認」を押します。直してほしいときは、理由を書いて「差戻し」を押します。
  5. 承認済みになったら配信方法を選び、「配信開始」か「予約する」を押します。承認しただけでは送信されません。
  6. 配信状況で、終わるまで見届けます。失敗、不明、配送の結果も確かめます。

予約は、承認済みの画面で行います。日本時間で、5分後から90日後までの日時を選べます。確定したら、「予約済み」の表示と日時を確かめてください。日時を変えるときは、「予約の取消」が終わったことを確かめてから、予約し直します。

宛先を扱う

  • 「宛先」では、メールアドレスが完全に一致するものを検索できます。
  • 新しく登録するには、本人が同意した日時、同意を得た経路、購読する配信リストが必要です。
  • 退会の連絡を受けたら「全停止」にします。1つの配信リストだけ止めるときは、その配信リストを選んで止めます。
  • 登録済みの宛先に配信リストを追加するとき、購読を再開するとき、完全削除するときは、管理者に頼んでください。
  • 管理者が購読を再開するときは、今回本人が同意した配信リストをすべて選びます。選ばなかった配信リストは停止になります。

CSVの条件は、UTF-8、2MiB以下、データの行が20,000行以下です。先頭の行は email,name,consent_at,consent_source,consent_version,topics にします。配信リストは内部名で書き、複数あるときはセミコロンで区切ります。

「新規登録だけ」は登録済みの宛先を変更しません。「既存の名前・停止を更新」は、列を email,name,stop にします。空の名前・stopは変更しません。stopは ALL か配信リストの内部名（複数は | 区切り）です。ALLの行に名前は書けません。購読の追加・再開や、未登録の宛先の作成は行いません。

どちらも、ファイルを送った後に確認画面で件数の内訳と変わる項目を確かめ、「内容を確認して反映」を押します。「取りやめる」も選べます。確認画面は24時間で期限切れになります。反映後は取込IDと、行番号ごとの結果コードを確かめてください。

管理者・配信担当は、宛先の詳細の「配送の記録」で直近180日の記録を確認できます。索引に見つからないことは未配送・未受付の証拠ではありません。「SESの受付」は相手サーバーへの配送とは別です。

送信の準備状況

配信画面の上に、停止スイッチ、送信元の認証、配送記録、監視、受入記録、送信枠などを表示します。「止まっています」「取得できません」の項目は、表示された担当者と次の操作を確認してください。取得できない項目を正常とは扱いません。

受入確認を進める（管理者）

  1. 「設定」の「受入確認」で新しい検査を始めます。検査は30日以内に確定してください。
  2. 必須試験を実施し、試験ごとに結果と確認内容を記録します。復旧のテスト送信は配信画面でこの検査を選び、理由を記入して実行します。結果は検査に残ります。
  3. 試験ごとに証跡ファイル（1MiB以下）を登録します。メール原文は通常画面に表示しません。
  4. すべての必須試験の合格と証跡を確かめて確定します。不合格がある場合は配信を止めます。設定やDNSが検査開始後に変わった場合は、新しい検査を始めます。

受入記録は90日間有効です。残り日数と失効の理由は設定画面に表示します。期限の30・14・7・1日前と期限切れを管理者へ通知します。

スタッフを管理する（管理者）

「スタッフ」で追加、役割変更、有効化・無効化、認証アプリの初期化、パスワードの再設定ができます。追加した人は案内メールの仮パスワードでログインし、パスワード変更と認証アプリの登録を行います。管理者は2人以上にしてください。自分自身の変更は別の管理者に依頼します。有効な管理者が2人未満になる無効化・役割変更はできません。初期状態で1人の場合は、先に管理者を追加してください。

変更にはログインから15分以内の認証が必要です。時間が過ぎるとログアウトしますので、ログインし直してください。管理者がログインできない場合はAWSの管理者に復旧を依頼します。

結果を読む・止める

  • 「送信済み」は、SESが受け付けた数です。
  • 「配送」は、相手のメールサーバーが受け取った数です。
  • どちらも、受信トレイに届いたことや、読まれたことを示すものではありません。
  • 「完了」になっても、失敗や不明が含まれていることがあります。
  • 「停止済みのため送らなかった」は、送信の直前に配信停止が分かった宛先の数です。失敗の数には含めません。

間違いに気づいたら「一時停止」を押し、管理者に連絡してください。「中止」した配信は再開できません。SESがすでに受け付けたメールは取り消せません。「要確認」や「不明」の宛先には、自分の判断で送り直さないでください。

操作できないとき

  • ボタンが押せない：そばの説明を読んでください。権限がない、下書きを保存していない、配信の状態が合わない、などが理由です。
  • 「他の人が先に操作しました」：入力した内容を控えてから、「読み込み直す」を押します。
  • 「設定を変更したため、送信元の確認をやり直しています」：組織設定を保存した直後です。数分待ってから、もう一度操作します。
  • 「通信結果を確認できません」：同じ操作を繰り返さないでください。配信や取込の結果を読み込み直して確かめます。
  • 受入記録の期限切れ・設定の変更：管理者が設定画面で検査を始め、配信画面でその検査を選んで復旧のテスト送信を行います。試験結果と証跡がそろったら、設定画面で確定します。
  • 「要確認：開始処理の有無を確認できません」などの表示：同じ操作を繰り返さず、別の配信も作らずに、管理者に連絡してください。
  • 認証、監視、送信枠、全体停止のエラー：管理者に連絡してください。配信を作り直して避けようとしないでください。
  • 「期限までに送り終えられません」（CAPACITY_INSUFFICIENT）：対象件数と期限までの送信可能件数を確かめます。管理者に日次上限の引上げを依頼するか、同じ内容の期限を延ばして承認し直してください。まだ1通も送っていません。
  • 「承認の最大件数を超えた」（AUDIENCE_EXCEEDS_APPROVAL）：承認待ちへ戻ります。内容は固定したまま、管理者・承認者が件数と期間を見直して承認します。承認不要の組織でも必要です。
  • 「承認された送信期間の範囲外」（OUTSIDE_APPROVED_WINDOW）：即時開始なら現在、予約なら予約日時が承認の開始日時以上・期限より前になるようにします。
  • 「送信期限を過ぎた」（DEADLINE_PASSED）：残りを送らず中止しました。未送信件数を確認してください。開始後は承認の期限と最大7日の早い方までです。
  • 「予約日時から15分を過ぎても開始していません」（SCHEDULE_DELAYED）：他の配信の終了待ちなどを管理者が確かめます。予約は最も早い開始時刻です。期限まで始まらなければ送らず中止します。
  • 「配送の記録が不足」（EVENTS_MISSING）：5分区間の受付数と、観測猶予後のSES・配送記録の件数を比べて止めています。1件でも記録があれば正常という判定ではありません。「件数が少ないため判定していません」は正常の証拠ではありません。
  • 「結果不明の調査」（UNKNOWN_REVIEW_OPEN）：管理者が結果の宛先と配送の記録を調べ、根拠を書いて「調査を継続」または「送り直さず調査を終了」を記録します。OPENのまま3日を過ぎると通知し、その後は7日に1回まで通知します。元のアドレスは保存中の30日間だけ管理者に表示できます。調査を終了すると宛先の保存を消します。自動で再送はしません。

問い合わせるときは、日時、環境、配信IDまたは取込ID、押したボタン、画面の説明、問い合わせ番号を伝えてください。パスワード、認証コード、会員名簿、配信停止のURLは、ふだんの連絡に含めないでください。
