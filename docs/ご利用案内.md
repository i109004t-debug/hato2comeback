## 1. HT2 とは

HT2 は、ファンクラブなどの会員組織（以下「配信組織」）が、自分たちの独自ドメインから、配信に同意した会員へ会報やお知らせをまとめて届けるためのメール配信システムです。

- AWS のサービスと、公開しているソースコードだけで動きます。外部のライブラリは使いません。
- メールの送信には Amazon SES を使います。配信停止やバウンス（届かなかったメール）の管理も、SES の仕組みで行います。
- 配信組織ごとに、専用の AWS アカウントで動きます。ほかの組織と環境を共有することはありません。
- メールサーバーを自分たちで建てる必要はありません。

HT2 は、メール配信に迷っているファンクラブの運営者のための公共財として公開しています。成り立ちは [README](../README.md) を見てください。

## 2. できること

- **宛先を管理**：会員のメールアドレスを1件ずつ登録するか、CSVファイルでまとめて取り込めます。
- **配信リストを使い分け**：「会報」「イベント案内」など、配信リスト（最大20）ごとに購読を管理します。
- **1画面で作成**：配信リスト・件名・本文を入力し、プレビューとテスト送信で確かめられます。
- **承認してから配信**：申請と承認を経て、すぐに配信するか、日時を指定して予約します。
- **結果を確認**：送信の受付、受信側への配送、バウンス、配信停止などの件数を確かめられます。
- **配信停止は SES が処理**：会員は、メールの「登録解除」や本文のURLから、いつでも配信を止められます。
- **安全の仕組み**：結果が分からないメールは、自動で送り直しません。バウンスや苦情が増えたときなどは、自動で止まります。

### 対象範囲

| 項目 | 内容 |
|---|---|
| 配信先 | メール事業者の制限なし（Gmail、Yahoo!メール、Outlook.com、iCloud、携帯キャリアのメール、プロバイダのメールなど） |
| 送信元 | 配信組織が管理する独自ドメイン1つと、その配下のアドレス（例：`info@fc.example.jp`） |
| 本文 | テキストメールだけ（日本語に対応） |
| 宛先の登録 | 1件ずつの登録、CSVでの一括登録（新しい宛先だけ） |
| 配信方法 | すぐに配信、予約配信（5分後から90日後まで） |
| 規模 | 1回の配信で最大10万件 |
| 対象外 | HTMLメール、差し込み（宛名の自動挿入）、添付ファイル、開封・クリックの計測、会員自身による登録フォーム、外部のアカウント（Amazon アカウントなど）でのログイン |

## 3. 導入するには

HT2 を使うには、配信組織が自分で AWS に HT2 を構築します。運営スタッフが AWS を操作する必要はありません。構築は、AWS の管理者が担当します。

### 3.1 用意するもの

| もの | 内容 |
|---|---|
| AWS アカウント | 支払い方法の登録が必要です。開発用・検証用・本番用の3つに分けることを勧めています |
| 独自ドメイン | 差出人のアドレスに使います。DNS を編集できる必要があります |
| メールを受け取れる場所 | 会員からの返信、DMARC の集計レポート、AWS からの通知を受け取ります |
| 担当者 | AWS の管理者（構築と監視）と、運営スタッフ（配信・承認） |

### 3.2 費用と時間の目安

- **費用**：固定費は1環境あたり月に約15ドルで、ほかに1,000通あたり約0.1ドルの送信料がかかります。開発・検証・本番の3環境では、固定費は月に約45ドルです。ドメインとメール受信サービスの費用は別です。内訳は [README](../README.md) の「費用と時間の目安」を見てください。
- **時間**：初めての構築では、最初のテスト送信まで数日から2週間ほどかかります。ドメインの認証（最大72時間）や、SES の本番利用の審査（おおむね1日）など、AWS 側の待ち時間があるためです。

### 3.3 進め方

1. AWS の管理者が、[AWS導入手順書](AWS導入手順書.md)に従って、AWS の契約、アカウントの分割、ドメインを準備します。
2. [構築手順書](構築手順書.md)に従って、開発用（dev）、検証用（stg）、本番用（prod）の順に HT2 を構築します。
3. 受入試験に合格したら、[利用者操作手順書](利用者操作手順書.md)の引継ぎ表を埋めて、運営スタッフに渡します。
4. 日々の監視と障害への対応は、[運用手順書](運用手順書.md)に従います。

## 4. 役割とできること

| 役割 | できること |
|---|---|
| 管理者 | 組織設定（差出人、法定表示、承認の要否、送信速度、テスト送信先）、停止した会員の購読の再開、完全削除、システムが止めた配信の再開、要確認の判断、受入確認の登録、監査ログの閲覧、その他すべて |
| 配信担当 | 宛先の登録・取込・配信停止、配信の作成・テスト送信・申請・開始・予約・一時停止・中止 |
| 承認者 | 配信の承認・差戻し・一時停止・中止 |
| 閲覧者 | 配信履歴と結果の閲覧（宛先のアドレスは一部を伏せて表示） |

- アカウントの作成、役割の変更、無効化は、AWS の管理者が行います。運営画面には、スタッフを管理する機能はありません。
- 申請した本人は、その配信を承認できません。
- 自分たちで止めた配信は、管理者・配信担当・承認者が再開できます。システムが自動で止めた配信を再開できるのは、管理者だけです。

## 5. 使い始めるまで

### 5.1 管理者と AWS の管理者が行う準備

運営スタッフが配信を始める前に、組織の管理者と AWS の管理者が次の準備をします。

1. 配信組織用の AWS アカウントに HT2 を構築し、配信リストを決めます。
2. 送信元ドメインの DNS に、SES が示す認証の設定（DKIM、MAIL FROM、SPF、DMARC）を登録します。
3. SES の本番利用を申請します。
4. 運営スタッフのアカウントを作り、役割を割り当てます。
5. 運営画面の「設定」で、組織設定（6節）を登録します。
6. 主要なメール事業者のテスト用アドレスで受信を確かめ、その結果を「受信確認の記録」として登録します（11節）。
7. 1日の送信上限を、少ない量から始める値に設定します。

**受信確認の記録がないと、本番の配信は始められません。**

### 5.2 運営スタッフの初回ログイン

1. 招待メールに書かれたメールアドレスと仮パスワードで、運営画面にログインします。仮パスワードの有効期限は7日です。
2. 新しいパスワードを設定します。12文字以上で、英大文字・英小文字・数字・記号をすべて含めてください。
3. スマートフォンの認証アプリ（ワンタイムパスワードを表示するアプリ）を登録します。**二要素認証は全員必須です。**
4. 次回からは、メールアドレス・パスワード・認証アプリのコードでログインします。

- ログインの状態は、最長8時間で切れます。
- パスワードを忘れた場合は、ログイン画面からメールで再設定できます。
- 認証アプリを使えなくなった場合や、アカウントを止めたい場合は、AWS の管理者に連絡してください。

## 6. 組織設定（管理者）

「設定」画面で次の項目を登録します。管理者以外は閲覧だけできます。

| 項目 | 内容 |
|---|---|
| 差出人 | 差出人名（1〜64文字）と、アドレスの `@` より前の部分。ドメインは構築のときに決めた送信元ドメインに固定です |
| 返信先 | 任意。会員の返信を受け取れるアドレスにします |
| 法定表示 | 送信者の名称、所在地、問い合わせ先（メールアドレス・URL・電話番号のいずれか）。**未設定だと配信を申請できません** |
| 承認の要否 | 既定は「必要」。スタッフが1人だけの組織に限り、管理者が「不要」にできます（監査ログに残ります） |
| 送信速度の上限 | 1秒あたりの送信数。既定は毎秒10通です |
| テスト送信先 | 最大5件。宛先として登録済みで、配信リストを購読しているアドレスに限ります |

- 差出人・返信先・法定表示には、`{{` と `}}` を含めないでください。
- テスト送信先は、先に「宛先」で登録してから設定します。初めて保存するときは、テスト送信先を空のままにしてください。
- 組織設定を保存すると、送信元の確認が自動でやり直されます。終わるまでの数分間は、テスト送信や配信の開始が「設定を変更したため、送信元の確認をやり直しています。数分後にもう一度お試しください。」と表示されて止まります。数分待ってから操作してください。

## 7. 宛先を管理する

「宛先」画面で、会員のメールアドレスと購読状態を管理します。宛先の情報は、SES の連絡先リストに保存されます。

### 7.1 1件ずつ登録する

アドレス、名前（任意）、**同意の日時と取得経路**（例：入会申込フォーム）、同意した案内文の版（任意）、購読する配信リストを入力します。同意の日時と取得経路がない宛先は登録できません。

### 7.2 CSV でまとめて取り込む

**CSV で登録できるのは新しい宛先だけです。** すでに登録されているアドレスは、CSV に含まれていても変更されずに飛ばされます。配信を停止した会員が、CSV の取込で購読に戻ることはありません。

| 列名 | 必須 | 内容 |
|---|---|---|
| `email` | ○ | メールアドレス |
| `name` | 任意 | 名前（50文字まで） |
| `consent_at` | ○ | 会員が配信に同意した日時（ISO 8601形式。未来の日時は不可） |
| `consent_source` | ○ | 同意の取得経路や記録の所在（100文字まで。例：入会申込フォーム） |
| `consent_version` | 任意 | 同意した案内文の版など（30文字まで） |
| `topics` | ○ | 購読する配信リストの内部名。複数ならセミコロンで区切ります（例：`kaiho;event`）。内部名は管理者に確認してください |

先頭行は次のとおりです。

```csv
email,name,consent_at,consent_source,consent_version,topics
```

- 文字コードは UTF-8（BOM 付きも可）、1ファイル2MiB以下・20,000行以下です。
- 日時の記入例は `2026-10-20T10:30:00+09:00` です。**実際に同意を得た相手の、実際の日時と取得経路**を書いてください。
- 上の表にない列があると、ファイル全体がエラーになります。
- 取込の処理中は、1件ずつの登録と別の取込はできません。
- **SES のサンドボックス（本番利用の承認前の状態）では、CSV 取込を使えません。** 開発用の環境などでは、1件ずつ登録してください。

### 7.3 メールアドレスの扱い

- アドレスは小文字にそろえて登録します。使える文字は半角英数字と記号だけです。
- 先頭や末尾にドットがある、ドットが連続するなど、古い携帯電話のアドレスに見られる形式は、届かないおそれがあるため登録できません。
- Gmail（`gmail.com`・`googlemail.com`）は、アドレスの中のドットや `+` 以降を除いた形で1件にまとめます。同じ受信箱に何通も届いたり、1つを止めても別の表記に届き続けたりすることを防ぐためです。

### 7.4 購読の変更・停止・再開・削除

| 操作 | できる人 | 内容 |
|---|---|---|
| 配信リストの追加 | 管理者 | 本人の新しい同意が必要です |
| 配信リスト別の停止・全停止 | 管理者、配信担当 | 理由は監査ログに残ります |
| 購読の再開 | 管理者だけ | 一度止めた会員が改めて希望したときだけ。**新しい同意の証跡**（本人からの申込メールなど）が必要です。今回同意した配信リストをすべて選び、選ばなかった配信リストは停止になります |
| 完全削除 | 管理者だけ | 個人情報の削除を求められたときに、理由を入力して行います。削除したアドレスは、以後の登録や取込で受け付けません |

- 退会の連絡を受けたときは、全停止にしてください。アドレスと停止の状態が残るので、誤ってまた送ることを防げます。
- スタッフが止めた配信は HT2 の中に記録し、送信の直前に必ず確かめます。会員が開く SES の配信停止のページでは、購読中のまま表示されることがありますが、HT2 からは送りません。
- 宛先の検索は、アドレスの完全一致だけです。
- 1件を表示すると、配送できない宛先として SES に登録されているか（抑止の状態）と、その理由・日時を確かめられます。

## 8. 配信を作成して開始する

### 8.1 配信画面

```text
┌─────────────────────────────── HT2 ──────────────────────────────┐
│ ○○ファンクラブ／ログイン中: 山田    [宛先] [配信履歴] [設定]       │
├───────────────────────────────────────────────────────────────────┤
│ 差出人      ○○ファンクラブ <info@fc.example.jp>   返信先 support@… │
│ 配信リスト  [会報 ▼]          購読者 約1,234件（前日時点）         │
│ 件名        [____________________________________________]       │
│ 本文        [                                            ]       │
│             [             テキスト本文                 ]       │
│ フッター    （自動）発行者・所在地・問合せ先・配信停止URL          │
│ [プレビュー] [テスト送信] [下書き保存] [承認申請]                  │
├───────────────────────────────────────────────────────────────────┤
│ 承認済みになったら：配信方法 (●) 配信開始を押したら送る ( ) 予約   │
│ 配信状況    送信済○／失敗○／不明○／停止済み○ ・ 配送○／バウンス○  │
│             [一時停止] [再開] [中止]                              │
└───────────────────────────────────────────────────────────────────┘
```

※ 説明のためのイメージです。実際の画面とは配置が違います。件数は架空の数字です。

### 8.2 手順

| 手順 | 操作 | 担当 | 確認すること |
|---|---|---|---|
| 1 | 配信リストを選ぶ | 配信担当 | 購読者数の目安（前日時点） |
| 2 | 件名と本文を入力し、下書き保存 | 配信担当 | 誤字、日時、URL、連絡先 |
| 3 | プレビュー | 配信担当 | 本文の後ろに自動で付くフッター（法定表示と配信停止の案内） |
| 4 | テスト送信 | 配信担当 | 実際の受信画面での表示、配信停止のリンク |
| 5 | 承認申請 | 配信担当 | 申請した時点で、件名・本文・フッターが固定されます |
| 6 | 承認または差戻し | 承認者（申請者以外） | 画面に表示される、固定済みの内容 |
| 7 | 配信方法を選んで、配信開始または予約 | 配信担当 | 配信方法と日時 |
| 8 | 配信状況の確認 | 全員 | 9節 |

- **入力の決まり**：件名は1〜200文字で、改行は入れられません。本文はテキストで50KiB以下です。件名・本文とも、`{{` と `}}` は使えません。
- **フッター**：送信者の名称・所在地・問い合わせ先と、配信停止のURLが、本文の後ろに自動で付きます。編集はできません。
- **短縮URL**：本文に短縮URLらしいリンクがあると、注意が出ます。迷惑メールと判定されやすくなるため、使わないでください。
- **テスト送信**：送り先は、組織設定のテスト送信先（最大5件）だけです。テスト送信も1日の送信件数に数えます。ほかの配信の送信中は、テスト送信できません。
- **差戻し**：理由を付けて下書きに戻ります。直して申請し直すと、新しい版として承認を受けます。
- **承認不要の設定**のときは、申請と同時に承認済みになります。

**承認された内容は変更できません。** 直したいときは、その配信を中止して、新しい配信を作り直してください。

### 8.3 配信方法と予約

配信方法と日時は、**承認済みになってから**選びます。下書きや承認待ちの間は予約できません。

- 予約できるのは、5分後から90日後まで（日本時間）です。
- 毎時0分は受信側が混み合い、遅れたり受け取りを制限されたりしやすくなるため、画面で注意が出ます。5分などにずらしてください。
- 予約は、開始されるまで取り消せます。
- 予約した時刻にほかの配信が送信中なら、その配信が終わってから始まります。
- **「配信開始」や「予約する」を押すと、確認の画面は出ずにそのまま進みます。** 押す前に、内容・配信リスト・配信方法・日時を確かめてください。

### 8.4 配信の宛先

**宛先は、送信を始めた時点で配信リストを購読している会員です。** 承認や予約の後に配信を停止した会員には送りません。送る順番は配信ごとに混ぜて、同じメール事業者へ集中しにくくしています。

### 8.5 配信を開始できないとき

開始・予約の開始・再開のたびに、システムが送信の条件を確かめます。条件を満たさないと配信は始まらず、理由が画面に表示されます。予約した配信が、開始の時刻に条件を満たさなかった場合は「承認済み」に戻ります。原因を直してから、開始し直してください。

| 画面の表示（例） | 意味 | 対応 |
|---|---|---|
| 法定表示などの組織設定が足りない | 組織設定が足りない | 管理者が設定します |
| 受信確認の記録がない、または期限切れ・設定変更で無効 | 受入確認が済んでいない | 管理者が受入確認をやり直します（11節） |
| 送信元ドメインの認証に異常があります | DNS か SES の状態に問題がある | AWS の管理者が DNS と SES の状態を確かめます |
| 設定を変更したため、送信元の確認をやり直しています | 組織設定を変えた直後で、送信元の確認をやり直している | 数分待ってから、もう一度試します |
| バウンス率や苦情率の警報が出ています | 組織全体の評判の数値が悪い | 原因を直し、警報が解除されるまで待ちます |
| SESの24時間の送信枠が足りません | SES の送信枠が足りない | 枠が戻るのを待ちます。いつも足りなければ、AWS の管理者が引き上げを申請します |
| 全体の停止スイッチが入っています、SESが送信を止めています | 送信が止められている | AWS の管理者が理由を確かめます |
| 配送の記録や監視の状態を確認できません など | 記録や監視の仕組みが正しく動いていない | AWS の管理者が復旧します |
| 開始処理を作成できませんでした（または予約を作成できませんでした）。配信は承認済みに戻っています | 開始の処理を作れなかった | 原因を直してから、もう一度開始または予約します |
| 要確認：開始処理の有無を確認できません（または予約の有無を確認できません） | 開始の処理ができたかどうか分からない | 同じ操作を繰り返さず、別の配信も作らずに、管理者に連絡します |
| 他の人が先に操作しました | 他の人が先に操作した | 画面を読み込み直します |

### 8.6 配信前の確認事項

- [ ] 差出人と返信先が正しい
- [ ] 配信リストが正しく、宛先は配信に同意した会員だけである
- [ ] 件名と本文に誤りがなく、別の送り手を装う表現がない
- [ ] テスト送信で、表示と配信停止のリンクを確かめた
- [ ] 承認を得ている
- [ ] 予約するなら、毎時0分を避けた

## 9. 配信中・配信後の見方

### 9.1 配信の状態

| 状態 | 意味 |
|---|---|
| 下書き | 編集できます |
| 承認待ち | 申請済みで、内容は固定されています |
| 承認済み | 開始または予約ができます |
| 予約済み | 指定した日時に開始します |
| 開始待ち | 送信の準備中、またはほかの配信の終了待ちです |
| 送信中 | 1通ずつ送っています |
| 一時停止中 | 止まっています。理由が表示されます |
| 要確認 | 処理が途中で止まり、管理者の判断が必要です（9.5節） |
| 完了 | 送信の処理が終わりました。全員に届いたという意味ではありません |
| 中止 | 中止しました。残りは送りません |

### 9.2 件数の見方

| 表示 | 意味 |
|---|---|
| 送信済み（SES受付） | SES が送信を受け付けた件数。配送できない宛先への送信も含みます |
| 配送 | 受信側のメールサーバーが受け取った件数 |
| 配送遅延 | 受信側が一時的に受け取りを遅らせている件数。SES が自動で再試行します |
| バウンス | 届かなかった件数 |
| 苦情 | 受信者が迷惑メールと報告し、SES に通知された件数。**Gmail と iCloud の苦情は通知されないため含まれません** |
| 購読設定の変更 | 会員が配信停止や配信設定を変えた件数（停止以外の変更も含みます） |
| 失敗 | アドレスの不備などで、SES が受け付けなかった件数 |
| 不明 | 通信の問題などで、受け付けられたか分からない件数（9.5節） |
| 停止済みのため送らなかった | 送信の直前に、配信停止や完全削除が分かったため、送らなかった件数。失敗には含めません |

- 件数は10秒ごとに更新されますが、配送やバウンスなどは数分遅れて反映されます。
- **「配送」は、受信トレイに届いたことや、読まれたことを意味しません。** 迷惑メールフォルダーに振り分けられることもあります。受信トレイへの到達は、HT2 では確かめられません。

### 9.3 1日の送信上限

受信側に急に大量のメールが届くと、受け取りを制限されることがあります。そのため、組織の1日の送信件数に上限を設け、少ない量から段階的に増やします（初期値の案は1日1,000通）。テスト送信も件数に数えます。

- 上限に達した配信は自動で待機し、**翌日0時5分（日本時間）に条件を確かめ直してから、続きを送ります。** 画面に再開予定の時刻が表示されます。
- 条件を満たさなければ、そのまま一時停止します。この場合は、管理者が原因を直して再開します。
- 上限の引き上げは、配送遅延・バウンス・苦情の状況を確かめたうえで、AWS の管理者が行います。初めての配信や、長く配信を休んだ後も、少ない量から始めます。
- 開始から7日たっても終わらない配信は、古い内容を送り続けないよう、自動で中止します。

### 9.4 一時停止・再開・中止

- **一時停止**：送信中の配信を止めます。数秒以内に、まだ送っていない分の送信が止まります。
- **再開**：止めた所から続けます。自分たちで止めた配信は、管理者・配信担当・承認者が再開できます。
- **中止**：残りを送らずに終えます。確認のダイアログが出ます。中止した配信は再開できません。
- 一時停止から7日たった配信は、自動で中止になります。

**すでに SES が受け付けたメールは、一時停止や中止をしても取り消せません。**

次のような場合、送信中の配信は自動で一時停止し、管理者に通知されます。**再開できるのは管理者だけです。** 管理者は原因を確かめて直し、テスト送信で受信を確かめてから再開します。

| 止まる理由（例） | 意味 |
|---|---|
| バウンス率・苦情率の警報 | 組織全体の評判の数値が、しきい値を超えた |
| 配信のバウンス率・配送遅延率 | この配信で、届かない・遅れる宛先の割合が高い。受信側が受け取りを制限している兆候です |
| 配送の記録が届かない | 送ったのに、配送やバウンスの記録が届かない。記録の仕組みの故障を疑います |
| 送信元の認証の異常 | DNS の設定が変わったなどで、送信元ドメインの認証が確かめられない |
| SES の停止・応答の不安定 | SES が送信を止めた、または結果の分からない応答や速度の制限が続いた |
| ほかの配信の終了待ちが長い | ほかの配信が終わるのを長く待ち続けた。管理者が実行の状況を確かめます |
| SES の24時間の送信枠 | SES の送信枠を使い切った。枠は直近24時間の合計なので、日付が変わっても戻りません |

### 9.5 結果が分からない宛先と「要確認」

- **結果が「不明」の宛先には、自動で送り直しません。** 二重に届くことを避けるためです。
- 処理が途中で止まると、配信は「要確認」になり、最大20件の宛先について、送ったかどうかが分からなくなります。管理者が配送の記録を確かめたうえで、「飛ばして再開」「送り直して再開」「中止」のどれかを選びます。

## 10. 会員からの配信停止

- 会員は、メールソフトの「登録解除」ボタン（ワンクリック解除）か、本文の最後にある配信停止のURLから手続きできます。手続きは SES が受け付け、以後その会員には送られません。
- 配信停止のURLのページでは、配信リストごとの停止と、すべての停止を選べます。このページは英語で表示される場合があるため、フッターに日本語の案内を入れています。
- 「登録解除」ボタンを表示するかどうかは、受信側のメールソフトが決めます。表示されない場合も、本文のURLから止められます。
- 届かなかったアドレス（宛先不明など）と、迷惑メールとして報告された宛先は、SES が自動で「配送しない宛先」（抑止）に登録します。抑止を解除できるのは、AWS の管理者だけです。
- 止めた会員を、運営スタッフが購読に戻すことはできません。会員が改めて希望した場合だけ、管理者が新しい同意の証跡を付けて再開します。

## 11. 受入確認（本番で配信を始める前に）

本番の環境では、主要なメール事業者で受信を確かめた記録（受入記録）がないと、会員への配信を始められません。

- 受入記録は、AWS の管理者と HT2 の管理者が、[構築手順書](構築手順書.md)の6節に従って、試験と証跡をそろえてから登録します。
- 受入記録が有効なのは、登録から90日以内で、送信の設定や DNS が変わっていない間だけです。
- 期限が切れたり設定を変えたりしたときは、確認をやり直します。管理者は「受入確認を再検証する」を選び、理由を書いて、登録済みのテスト送信先に送れます。手順は[利用者操作手順書](利用者操作手順書.md)の8節にあります。

## 12. 安全に利用するためのお願い

HT2 は、会員の意思に沿ったメール配信のためのシステムです。

- 配信に同意した会員にだけ送ってください。購入した名簿や、入手元の分からないアドレスの一覧、長く使っていない名簿は使わないでください。
- 差出人名や件名で、ほかの組織や人を装わないでください。
- 短縮URLや、組織と関係のないリンクは使わないでください。
- 会員が配信停止を希望したら、その意思を尊重してください。
- 会員のアドレスの一覧を、ふだんのメールやチャットで送ったり、必要以上に保管したりしないでください。
- フィッシング、詐欺、なりすまし、マルウェアの配布などには使わないでください。

特定電子メール法に従い、すべての配信の本文の最後に、送信者の名称・所在地・問い合わせ先と、配信停止の方法を自動で表示します。同意の日時と取得経路も、宛先ごとに記録します。ただし、法令に合っているかの最終的な判断は、配信組織の責任です。運用を始める前に、表示の内容や同意の記録の扱いを確かめてください。

## 13. よくある質問

**Q. Gmail 以外のアドレスにも送れますか？**  
A. 送れます。メール事業者の制限はありません。

**Q. 自分の Amazon アカウントや Google アカウントでログインできますか？**  
A. できません。管理者から発行されたアカウントに、パスワードと認証アプリの二要素認証でログインします。

**Q. `myname@gmail.com` を差出人にできますか？**  
A. できません。差出人は、配信組織が管理する独自ドメインのアドレスに限ります。

**Q. 1日に何通まで送れますか？**  
A. 組織の1日の送信上限と、SES の送信枠の両方の範囲内です。1日の上限は少ない量（案：1,000通）から始め、受信側の状況を見ながら、AWS の管理者が引き上げます。送信の速さは既定で毎秒10通で、1万件なら約17分です。1回の配信は最大10万件です。

**Q. 費用はどのくらいかかりますか？**  
A. 固定費は1環境あたり月に約15ドルで、ほかに1,000通あたり約0.1ドルの送信料がかかります（2026年11月時点の概算）。詳しくは [README](../README.md) を見てください。

**Q. CSV に書いた人には、必ず全員に届きますか？**  
A. いいえ。登録済みのアドレス、削除済みのアドレス、形式に問題のあるアドレスは取り込まれません。また、配信を停止した会員や、届かないと SES に登録された宛先には送られません。

**Q. 開発用の環境で CSV 取込が使えません。**  
A. SES のサンドボックス（本番利用の承認前の状態）では、CSV 取込を使えません。1件ずつ登録してください。

**Q. 組織設定を変えたら、テスト送信ができなくなりました。**  
A. 組織設定を保存すると、送信元の確認が自動でやり直されます。終わるまでの数分間は送信できません。数分待ってから、もう一度試してください。長く続くときは、AWS の管理者に連絡してください。

**Q. 配信を始めた後に、本文を直せますか？**  
A. 直せません。承認された内容は固定されます。まだ送っていない分を止めたい場合は中止し、新しい配信を作り直してください。

**Q. 「配送」と表示されたら、相手の受信トレイに届いたということですか？**  
A. いいえ。受信側のサーバーが受け取ったという意味です。迷惑メールフォルダーへの振り分けや、読まれたかどうかは分かりません。

**Q. 配信を止めたはずの会員に届いたと言われました。**  
A. 停止の手続きより前に、そのメールの送信が始まっていた可能性があります。宛先画面で購読の状態を確かめ、必要なら管理者に配送の記録の確認を頼んでください。SES が受け付けた後のメールは取り消せません。

**Q. スタッフが止めた会員が、配信停止のページでは購読中と表示されると言っています。**  
A. スタッフが止めた配信は HT2 の中に記録するため、SES のページには反映されないことがあります。HT2 は送信の直前に必ず停止を確かめるので、その会員には送りません。

**Q. 携帯キャリアのアドレスに届かないと言われました。**  
A. 受信側の迷惑メール設定で、送信元のドメインからの受信が拒否されている場合があります。会員に、送信元のドメインからのメールを受け取れるよう、受信設定の見直しをお願いしてください。宛先画面で、そのアドレスが配送しない宛先（抑止）になっていないかも確かめてください。

**Q. HTML メールや添付ファイルは送れますか？**  
A. 送れません。テキストメールだけです。

**Q. 過去の配信はいつまで見られますか？**  
A. 配信の記録は1年間残ります。1年を過ぎると、件名と本文は消え、件数だけが残ります（期間は案です）。

**Q. 使い方のサポートはありますか？**  
A. HT2 は公共財として公開しているもので、サポートの窓口はありません。組織の中では、HT2 の管理者が窓口になります。不具合の報告や改善の提案は、GitHub の Issue で受け付けています（対応を約束するものではありません）。

**Q. 配信のトラブルが起きたらどうすればいいですか？**  
A. 必要なら配信を一時停止し、配信履歴に表示される配信ID、起きた時刻、画面に出た理由を控えて、組織の管理者に連絡してください。会員のアドレスの一覧を、メールなどで送ることは避けてください。

## 14. 導入する組織が決めること

HT2 を導入する組織は、運用を始める前に次のことを決めて、この案内の写しや利用者操作手順書の引継ぎ表に書き込んでください。

- 運営画面のURLと、組織の中の問い合わせ窓口
- 1日の送信上限の初期値と増やし方、自動停止のしきい値（初期値は案です）
- 法定表示の内容、同意の記録の扱い、削除を求められたときの対応（必要に応じて専門家に確かめます）
- 記録の保持期間
- 障害のときと時間外の連絡方法

---

**HT2 は、送信元の正当性、会員の同意、確実な配信停止を守りながら、会報を届けるためのシステムです。**
