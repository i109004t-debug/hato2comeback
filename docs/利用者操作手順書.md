# HT2 利用者操作手順書

この手順書は、HT2の運営画面を使うスタッフ向けです。宛先の登録、メールの作成、承認、配信、結果の確認の方法を説明します。管理者向けに、スタッフの管理と受入確認の方法も説明します。HT2 の全体像と使い方の流れは、先に[HT2 ご利用案内](ご利用案内.md)で確かめてください。この手順書は、画面の操作を細かく説明します。

スタッフがAWSと契約したり、AWSの設定をしたりする必要はありません。用意するものは次の3つです。

- ブラウザ
- 管理者が発行した、自分専用のアカウント
- スマートフォンの認証アプリ（ログインの二要素認証に使います）

運営画面の上部にある「使い方」を押すと、操作の要点とエラーの説明をいつでも開けます。

AWSの管理者が行う準備は、[AWS導入手順書](AWS導入手順書.md)にまとめています。

## 1. 最初に受け取る情報

導入担当者は、次の表に実際の値を書き込み、スタッフに配ってください。このリポジトリには、特定の組織のURLや問い合わせ先は書いていません。

| 項目 | 導入担当者が記入する欄 |
|---|---|
| 組織名、本番の運営画面のURL | 未記入 |
| 練習用の運営画面のURL、練習に使ってよい宛先 | 未記入。本番の会員を練習に使わないでください |
| 本人の役割、初回ログインの案内が届く先 | 未記入。パスワードはこの表に書かないでください |
| HT2管理者（2人以上）と、ふだんの連絡方法 | 未記入 |
| AWSの管理者と、頼める作業の目安 | 未記入。目安の例は2.3節にあります |
| 障害のときや時間外の連絡方法 | 未記入 |
| 承認を頼む相手と、その連絡方法 | 未記入 |
| 配信リストの表示名と、CSVで使う内部名 | 未記入。例：会報 / kaiho |
| 差出人の名前とアドレス、返信を受け取る担当 | 未記入 |
| テスト送信先、1日に送れる上限、配信してよい時間帯 | 未記入 |
| 受入確認の次の期限と担当者 | 未記入 |

AWSの管理者は、構築が終わったら次のものをHT2管理者に引き渡します。

- 運営画面のURL
- 最初の管理者のアカウント
- テスト送信の確認結果

ほかのスタッフのアカウントは、HT2管理者が運営画面の「スタッフ」で作ります（9節）。HT2管理者は、スタッフ1人ずつについて、この表がそろっていることと、最初のログインができることを確かめてください。

## 2. ログインと役割

この節では、ログインの方法と、役割ごとにできることを説明します。

### 2.1 ログインする

1. 渡された運営画面のURLを開き、「ログイン」を押します。
2. 初回の案内メールに書かれたユーザー名と仮パスワードを入力します。
3. 新しいパスワードを設定します。
4. 画面の案内に従って、認証アプリを登録します。
5. 認証アプリに表示されたコードを入力します。これで二要素認証（MFA）が完了します。
6. 画面の上部に表示される名前と環境（本番か練習用か）を確かめます。

**確認すること**：本番と練習用を取り違えないよう、ブラウザのブックマークは名前を分けて保存してください。

作業が終わったら「ログアウト」を押します。共有のパソコンには、パスワードなどを保存しないでください。

次のような場合は、表に書かれたHT2管理者に連絡してください。

- 初回の案内の期限が切れた
- パスワードを忘れた
- 認証アプリを入れた端末をなくした

HT2管理者は、本人であることを確かめてから、「スタッフ」で対応します（9節）。管理者が誰もログインできないときは、AWSの管理者が復旧します。

アカウントや認証コードを、ほかのスタッフと共用しないでください。

### 2.2 役割

| 役割 | 主にできること |
|---|---|
| 管理者（admin） | 組織設定、スタッフの管理、受入確認、宛先の登録、配信、承認、購読の再開、完全削除、要確認と結果不明の判断、システムが止めた配信の再開 |
| 配信担当（sender） | 宛先の登録、CSV取込と一括更新、配送の記録の確認、下書き、テスト送信、承認申請、配信の開始と予約、一時停止と中止 |
| 承認者（approver） | 申請された内容と承認の範囲（最大件数・送信期限）の承認と差戻し、範囲を変えての承認し直し、配信の一時停止と中止 |
| 閲覧者（viewer） | 配信結果と宛先の閲覧。アドレスは一部を伏せて表示されます |

- 自分で申請した配信は、管理者であっても自分では承認できません。
- スタッフの追加や役割の変更は、HT2管理者が「スタッフ」で行います（9節）。変更は60秒以内に反映されます。
- 押せないボタンがあるときは、そのそばに理由が表示されます。

### 2.3 役割ごとの責任と、頼むときの目安

止まっている作業を誰に頼むかは、次の表で確かめます。目安は、導入する組織が決め直してかまいません。

| 役割 | 担当すること | 頼まれたときの目安 |
|---|---|---|
| 配信担当 | 日々の配信と宛先の管理 | — |
| 承認者 | 内容と範囲の承認 | 承認の依頼に、当日中に答えます |
| 管理者（HT2管理者） | 組織設定、スタッフ、受入確認、止まった配信・要確認・結果不明の判断 | 止まった配信の理由を、当日中に確かめます。受入記録は、期限の30日前から更新します |
| AWSの管理者 | システムの更新、DNSとSESの申請、1日の上限とSESの送信枠の引き上げ、配信リストの追加、抑止の解除、データの復元、鍵の管理、管理者が誰もログインできないときの復旧 | 1日の上限の引き上げと配信リストの追加は、3営業日で行います。復元は、当日に着手します |

- HT2管理者は2人以上にしてください。1人だけのときは、画面に警告が出ます。
- AWSの管理者とHT2管理者は、同じ人が兼ねてもかまいません。その場合も、連絡先と代わりの人を決めておきます。

## 3. 最初の1通を送るまでの流れ

ここでは、作成から配信までの全体の流れと、送れる状態かどうかの確かめ方を説明します。細かい操作は4節から6節を見てください。

### 3.1 全体の流れ

1. 管理者が「設定」で、差出人、法定表示（発行者の名前・所在地・問い合わせ先）、テスト送信先を確かめます。テスト送信先は、宛先として登録され、対象の配信リストを購読している必要があります。
2. 配信担当が「配信」を開き、画面の上の「送信の準備状況」を確かめます（3.2節）。
3. 「新しい配信を作成」を押します。
4. 配信リスト、件名、本文を入力し、「下書き保存」を押します。
5. 「プレビュー」で、本文、リンク、自動で付くフッターを確かめます。
6. 「テスト送信」を押します。テスト送信先に届いたメールで、表示と返信先を確かめます。
7. 直すところがあれば、直して保存し、もう一度確かめます。
8. 「承認の範囲」に最大件数と送信期限を入れます。「完了見込みを更新」を押して、見込みを確かめます（5.3節）。
9. 「承認申請」を押します。承認者に、配信IDと確認のお願いを連絡します。
10. 申請者とは別の承認者が、「配信履歴」から配信を開きます。固定された内容と承認の範囲を確かめて、承認します。
11. 配信担当が承認済みの配信を開き、配信方法を選んで、開始または予約します。**承認しただけでは送信されません。**
12. 「配信状況」で終わるまで見届けます。「失敗」「不明」の件数と配送の結果も確かめます。

**確認すること**：状態が「完了」になったこと。「完了」でも失敗や不明が含まれることがあるので、件数も確かめます。

スタッフが1人だけの組織では、管理者が承認を不要に設定できます。その場合は、申請するとすぐ承認済みになります。手順10は飛ばしてください。ただし、宛先が承認の最大件数を超えて承認待ちに戻ったときは、承認し直す必要があります（6.3節）。

本番での最初の配信は、AWSの管理者とHT2管理者が受入試験に合格してから行います。受入試験の代わりに、一般の会員に送ってはいけません。

### 3.2 送信の準備状況を見る

「配信」の画面のいちばん上に、「送信の準備状況」が表示されます。今送れるかどうか、止まっている理由、誰が何をすれば進むかが分かります。表示は60秒ごとに更新されます。

各行は「項目：状態／担当：次の操作」の形で表示されます。問題のない項目には、担当と次の操作は表示されません。管理者には、残り日数や件数などの詳しい内容も表示されます。

| 状態の表示 | 意味と、すること |
|---|---|
| 準備できています | この項目に問題はありません |
| 確認してください | 注意が必要な状態です。表示された担当者が、次の操作を確かめます |
| 止まっています | この項目のために、配信を始められません。表示された担当者に連絡します |
| 取得できません | 状態を確かめられませんでした。正常とはみなさず、表示された担当者に連絡します |

項目と、見ていること、担当は次のとおりです。

| 項目 | 見ていること | 担当 |
|---|---|---|
| 全体の停止スイッチ | 送信全体が止められていないか | AWSの管理者 |
| SESの本番利用・送信の有効 | SESの本番利用が認められ、送信が止められていないか | AWSの管理者 |
| 送信元の認証 | 送信元ドメインの認証の確認が新しく、合格しているか | AWSの管理者 |
| イベント発行先3つ | 配送の記録を集める3つの送り先が有効か | AWSの管理者 |
| 監視のアラーム | 必要な監視の警報がそろい、鳴っていないか | AWSの管理者 |
| 評判のアラーム | バウンス率や苦情率の警報が鳴っていないか | 管理者 |
| 受入記録 | 受入確認の記録が有効か。残りの日数 | 管理者 |
| 今日の残り枠とSESの24時間の残り | 今日送れる残りの件数と、SESの送信枠の残り | AWSの管理者 |
| 送信ロック | ほかの配信が送信中かどうか | 配信担当 |
| 要確認の配信 | 要確認の配信の件数 | 管理者 |
| システムが止めた配信 | システムが自動で止めた配信の件数 | 管理者 |
| 結果不明の調査が残っている配信 | 調査が終わっていない配信の件数 | 管理者 |
| 予約が遅れている配信 | 予約の時刻から15分を過ぎても始まらない配信の件数 | 管理者 |
| 管理者の人数 | 有効な管理者が2人以上いるか | 管理者 |
| 完全削除用の鍵の状態 | 完全削除の照合に使う鍵が使えるか。使えないと、登録・取込・購読の再開もできません | AWSの管理者 |

「準備状況を取得できません。AWSの管理者がシステムの状態を確認してください。」と表示されたときは、AWSの管理者に連絡します。

**確認すること**：配信を始める前に、「止まっています」と「取得できません」の項目がないこと。

## 4. 宛先を登録・変更する

この節では、「宛先」の画面で会員のアドレスを登録し、変更し、止める方法を説明します。

### 4.1 宛先を探す

「宛先」で、メールアドレスを完全に一致する形で検索できます。部分一致の検索はできません。検索すると、次の内容が分かります。

- 名前
- 購読している配信リスト
- 同意の記録
- 全停止かどうか
- 抑止（バウンスや苦情のため、SESが配送しないと判断した宛先）かどうか
- 配送の記録（管理者と配信担当だけ。4.9節）

配信リストと購読状態で絞り込むこともできます。一覧は50件ずつ表示され、「次へ」で続きを表示します。

### 4.2 1件ずつ登録する

1. 「個別登録・購読の変更」で、「操作」を「新規登録」にします。
2. 次の内容を入力します。
   - 「メールアドレス」
   - 「名前（任意）」
   - 「購読する配信リスト（複数選択）」で、本人が同意した配信リスト
   - 「同意の日時（日本時間）」と「同意の取得経路」
3. 「実行」を押します。
4. 登録したアドレスを検索して、内容を確かめます。

**確認すること**：検索した宛先の同意の記録と配信リストが、入力したとおりであること。

同意を得た経路には、「会員申込フォーム」のように、あとで確かめられる内容を書きます。本人の同意を確かめていない宛先は登録しないでください。

経路の欄には、メールアドレスを書かないでください。書くと「同意の取得経路にはメールアドレスを含めず、申込方法などを記入してください。」と表示されます。

### 4.3 変更する・止める

先に宛先を検索して、今の状態を確かめてから操作します。

| したいこと | 操作 |
|---|---|
| 名前を直す | 「操作」を「名前の変更・選んだ配信リストの追加購読」にして、名前だけを変更します |
| 退会の連絡を受けた | 「全停止（退会）」を実行し、確認の画面で「確定する」を押します。登録した名前も消えます |
| 1つの配信リストだけ止める | その配信リストを選び、「選んだ配信リストの停止（1つ選択）」を実行します |
| 新しい配信リストを追加する | 本人の新しい同意が必要です。管理者に頼んでください |
| 多くの会員の名前や停止をまとめて変える | CSVの一括更新を使います（4.8節） |

止めた配信は、ふつうの編集やCSVで元に戻そうとしないでください。

スタッフが止めた配信は、HT2の中に記録します。会員が開くSESの配信停止のページでは、購読中のまま表示されることがあります。それでも、HT2からは送りません。

### 4.4 購読を再開する（管理者）

一度止めた会員が、改めて配信を希望したときだけ使います。管理者が、新しい同意の日時、経路、理由を確かめて操作します。

**今回本人が同意した配信リストを、すべて選んでください。選ばなかった配信リストは停止になります。**

- ふつうの編集では、会員がSESで行った解除の状態を上書きしません。
- 再開の結果が分からないときや、同時に停止の操作があったときは、停止のままになります。この場合、管理者はAWSの運用担当に引き継いでください。

### 4.5 完全削除する（管理者）

「完全削除」は、会員から個人情報の削除を求められたときに使います。退会だけなら、完全削除ではなく「全停止（退会）」を使ってください。

1. 宛先を検索して、対象のアドレスであることを確かめます。
2. 「操作」を「完全削除」にします。
3. 「再開・完全削除の理由」に、削除の依頼を受けた経緯を書きます。
4. 「実行」を押します。
5. 確認の画面で「確定する」を押します。

**確認すること**：削除の結果を知らせる説明が、画面に表示されたこと。

削除したアドレスは、今後、登録もCSV取込もできなくなります。それぞれの保存先から消える時期は、次のとおりです。

| 保存先 | 消える時期 |
|---|---|
| SESの連絡先、画面の名前と同意、配送の記録 | すぐ |
| SESの抑止リスト | 数分以内。あとから自動で消します |
| アドレスを含む取込ファイル | 最長7日 |
| 宛先スナップショット（配信のときに作る宛先の一覧） | 配信の終了時、または結果不明の調査の終了時。最長30日 |
| バックアップと生の配送記録 | 最長90日 |

- 再登録を防ぐ照合値と停止の印は残ります。照合値から、アドレスに戻すことはできません。
- 期間は、組織の設定で短くなっていることがあります。
- 抑止リストからの削除に失敗したときは、AWSの管理者に通知が届きます。AWSの管理者が削除します。
- 「完全削除の記録を確認できません。AWSの管理者が鍵の状態を確認してください。」と表示されたときは、登録・CSV取込・購読の再開もできません。AWSの管理者に連絡します。

会員には、「配信・画面・SES からはすぐに消えます。アドレスを含む保管ファイルからは、最長90日で消えます。」と伝えます。

### 4.6 抑止された宛先

抑止は、バウンスや苦情のために配送しない状態です。本人の同意があっても、抑止は自動では解除されません。別のアドレスを作り直して避けようとせず、管理者に連絡してください。

### 4.7 CSVでまとめて登録する（新規登録）

CSV取込は、「検査」と「反映」の2段階で進みます。ファイルを送ると、HT2がまず検査して、確認画面に件数の内訳を出します。内容を確かめてから反映します。

使えるCSVの条件は次のとおりです。

- 文字コードはUTF-8。Excelなどで保存するときは「CSV UTF-8」を選びます。
- 大きさは2MiB以下。
- データの行は20,000行以下。
- SES のサンドボックス（本番利用の承認前の状態）では、CSV取込を使えません。「SESのサンドボックスではCSV取込を使えません。1件ずつ登録してください。」と表示されたら、1件ずつ登録してください。

列の意味は次のとおりです。

| 列 | 内容 |
|---|---|
| email | メールアドレス。必須です |
| name | 名前。任意で、50文字以内です |
| consent_at | 本人が同意した日時。時差を付けて書きます。例 `2026-10-01T10:00:00+09:00` |
| consent_source | 同意を得た経路。必須で、100文字以内です |
| consent_version | 同意した案内文の版。任意で、30文字以内です |
| topics | 配信リストの内部名。複数あるときは `;` で区切ります。表示名は書かないでください |

```csv
email,name,consent_at,consent_source,consent_version,topics
member1@example.jp,山田太郎,2026-10-01T10:00:00+09:00,会員申込フォーム,v1,kaiho
member2@example.jp,鈴木花子,2026-10-02T11:30:00+09:00,会員申込フォーム,v1,kaiho;event
```

この例のアドレスは、そのまま取り込まないでください。自分の組織の、同意を得たデータと内部名に置き換えて使います。

- 日時に未来の日時は書けません。
- 名前などにカンマ、改行、引用符が入るときは、CSVの決まりに従って引用符で囲みます。

取り込みの手順は次のとおりです。

1. 「宛先」の「CSV取込・一括更新」で、「形式」を「新規登録だけ」にします。
2. 「CSVファイル」でファイルを選び、「検査して確認画面へ」を1回だけ押します。
3. 「取込の確認・結果」に表示された取込IDを控えます。
4. 状態が「確認待ち（24時間以内に反映してください）」になるまで待ちます。処理中は画面が自動で更新されます。
5. 件数の内訳を確かめます。「全行」「登録・更新の対象」「対象外の行」を見ます。
6. 行番号ごとの結果コードと説明を確かめます。行番号は、見出しの行を1行目として数えます。
7. 内容がよければ「内容を確認して反映」を押し、確認の画面で「確定する」を押します。やめるときは「取りやめる」を押します。
8. 状態が「完了」になったら、「処理済み」と「登録失敗」の件数を確かめます。
9. 何件か検索して、同意と配信リストが正しいことを確かめます。

**確認すること**：「登録・更新の対象」の件数と、完了後の「処理済み」の件数が合っていること。

前の取込の結果は、「取込履歴」の「結果を表示」で開き直せます。

- 確認画面は24時間で期限切れになります。期限が切れると状態が「確認の期限切れ」になり、受け取ったファイルは消えます。反映するときは、もう一度ファイルを送ってください。
- 反映するときに、HT2は完全削除や登録済みの照合をやり直します。確認画面の後に状態が変わった行は、「確認後に状態が変わったため反映しません」として登録しません。
- 反映の処理中は、1件ずつの新規登録、別の取込、完全削除はできません。「宛先の登録・取込を処理中です。終わるまでお待ちください。」と表示されます。

CSVで登録できるのは、新しい宛先だけです。

- すでに登録されている宛先、完全削除した宛先、ファイル内の重複は登録されず、結果に理由が表示されます。
- 登録済みの会員の名前や停止を変えるときは、4.8節の一括更新を使います。購読の追加や再開は、管理者が1件ずつ行います。
- 結果が「要確認（管理者が確認してください）」になったときや、「通信結果を確認できません」と表示されたときは、同じファイルをもう一度送らないでください。取込IDを管理者に伝えてください。

### 4.8 CSVで名前と停止をまとめて更新する（一括更新）

登録済みの会員の名前と、配信の停止を、CSVでまとめて更新できます。退会した会員の一覧をまとめて止めるときなどに使います。

**一括更新では、購読を追加したり再開したりできません。登録されていないアドレスも、新しく登録しません。**

見出しの行は `email,name,stop` にします。列の意味は次のとおりです。

| 列 | 内容 |
|---|---|
| email | メールアドレス。必須です |
| name | 新しい名前。50文字以内です。空欄なら変えません |
| stop | 止める範囲。空欄なら変えません |

`stop` の書き方は次のとおりです。

- すべての配信を止めるときは、`ALL` と書きます。すべて止めると、名前も消えます。
- 一部の配信リストだけ止めるときは、内部名を書きます。複数あるときは、縦線 `|` で区切ります。
- `ALL` の行には、名前を書けません。

```csv
email,name,stop
member1@example.jp,山田花子,
member2@example.jp,,ALL
member3@example.jp,,event
member4@example.jp,,kaiho|event
```

この例は、1行目が名前の変更、2行目がすべての停止、3行目と4行目が配信リストごとの停止です。そのまま取り込まず、自分の組織のデータと内部名に置き換えてください。

1. 「CSV取込・一括更新」で、「形式」を「既存の名前・停止を更新」にします。
2. 「CSVファイル」でファイルを選び、「検査して確認画面へ」を1回だけ押します。
3. 表示された取込IDを控えます。
4. 状態が「確認待ち（24時間以内に反映してください）」になったら、件数の内訳を確かめます。
5. 「変わる項目：名前 ○件・停止 ○件」を確かめます。
6. 行番号ごとの結果を確かめます（下の表）。
7. 「内容を確認して反映」を押し、確認の画面で「確定する」を押します。

**確認すること**：状態が「完了」になったこと。何件か検索して、名前と停止が変わったことも確かめます。

| 結果の説明 | 意味と、すること |
|---|---|
| 名前か停止を更新 | 反映すると、名前か停止が変わります |
| 変更なし | 変わる項目がありません |
| 登録されていないため変更しません | このアドレスは登録されていません。新しく登録もしません |
| 完全削除済み | 完全削除したアドレスです。何もしません |
| 形式または確認後の状態変更のため反映しません | 行の書き方に誤りがあるか、確認画面の後に状態が変わっています。直して送り直すか、管理者に相談します |

- 結果には、行番号と結果コードだけが表示されます。アドレスは表示されないので、元のファイルと行番号で突き合わせます。
- 一括更新で止めた配信も、HT2の中に記録します。会員が開くSESの配信停止のページには反映されませんが、HT2からは送りません。
- 確認画面の期限と、反映中にできない操作は、4.7節と同じです。

### 4.9 配送の記録を見る（管理者・配信担当）

宛先の詳細には、「配送の記録」が表示されます。その宛先へのメールが、SESに受け付けられたか、相手のサーバーに届いたかを調べる入口です。

1. 「宛先を探す」で、メールアドレスを完全一致で検索します。
2. 「宛先の詳細」の「配送の記録」を見ます。

**確認すること**：調べたい配信の配信IDの行と、その種類と日時を確かめたこと。

直近180日の記録が、新しい順に最大200件表示されます。

| 種類の表示 | 意味 |
|---|---|
| SESの受付 | SESが送信を受け付けました |
| 相手サーバーへ配送 | 相手のメールサーバーが受け取りました。受信トレイへの到着とは別です |
| バウンス | 届きませんでした |
| 苦情 | 受信者が迷惑メールとして報告しました |
| 配送遅延 | 相手のサーバーが、受け取りを一時的に遅らせています |
| 拒否 | SESが送信を取りやめました |
| 購読変更 | 会員が配信停止や配信設定を変えました |
| 本文の作成失敗 | メールの本文を作れませんでした |

**記録が見つからなくても、届かなかった証拠にはなりません。** 記録は遅れて届いたり、抜けたりすることがあります。詳しく調べる必要があるときは、管理者がAWSの管理者に、生の配送記録の調査を頼みます。

閲覧者には、配送の記録は表示されません。

## 5. 作成、テスト、承認、予約

この節では、メールを作って確かめ、承認を受けて、配信の日時を決めるまでを説明します。

### 5.1 件名と本文を書く

- 本文はテキストだけです。大きさは50KiB以下です。
- 件名は200文字以内です。
- 件名と本文には、`{{` と `}}` を使えません。
- ファイルの添付や画像の挿入はできません。
- 案内するURLには、公式のURLを使ってください。短縮URLは使わないでください。
- ほかの送り手と間違われるような差出人名や件名は使わないでください。
- 発行者の名前、所在地、問い合わせ先、配信停止の案内は、フッターとして自動で付きます。

### 5.2 テスト送信する

1. 下書きを保存します。
2. 「テスト送信」を押します。送り先は、「設定」で登録した最大5件だけです。
3. 届いたメールで、表示を確かめます。プレビューだけで済ませず、実際のメールでも確かめてください。

**確認すること**：画面の「テスト送信の結果」に、送り先ごとの結果が表示されたこと。

- テスト送信も、1日に送れる件数に数えられます。
- 配信停止の試験は、テスト専用の宛先で行ってください。
- 結果が「不明」になったときは、続けて何度も押さないでください。

### 5.3 承認の範囲と完了見込み

承認では、内容のほかに「何件まで」「いつまでに」送ってよいかを決めます。これを「承認の範囲」と呼びます。配信担当が申請のときに提案し、承認者が確定します。

| 項目 | 内容 |
|---|---|
| 最大件数 | 送ってよい宛先の数の上限です。1件から100,000件まで入れられます |
| 送信期限（日本時間） | この日時までに送り終えます。申請・承認の1時間後から90日後まで選べます |
| 最も早い開始日時（任意・日本時間） | これより前には始めません。空欄なら、承認した時刻からです |

- 最初は、最大件数に購読者数の概算の1.2倍が入っています。100件単位で切り上げた値です。
- 最初の送信期限は、7日後です。
- 開始してから7日たっても終わらない配信は、送信期限の前でも中止します。

完了見込みは、次の手順で確かめます。

1. 「承認の範囲」に値を入れます。
2. 「完了見込みを更新」を押します。
3. 表示された見込みを読みます。

**確認すること**：「完了見込み：」の日時が表示され、「期限までに送り終えられません」と表示されていないこと。

- 完了見込みは、前日時点の購読者数と、1日に送れる上限、SESの送信枠からの概算です。実際の完了を保証しません。
- 「期限までに送り終えられません（不足 約○件）」と表示されたら、送信期限を延ばすか、管理者に1日の上限の引き上げを頼みます。
- 配信を始めるときにも、HT2がもう一度確かめます。

### 5.4 承認を申請する・承認する

「承認申請」を押すと、本文、件名、差出人、フッターが固定されます。承認の範囲は、提案として保存されます。

承認者は、次の手順で承認します。

1. 「固定した内容の確認」を読みます。
2. 「承認の範囲」の最大件数と送信期限を確かめます。必要なら直します。
3. 「完了見込みを更新」を押して、見込みを確かめます。
4. 「固定した内容を確認しました」にチェックを入れます。
5. 「承認」を押します。

**確認すること**：状態が「承認済み」になり、「承認済み：最大○件・…から…まで」と表示されたこと。

直してほしいところがあれば、「差戻しの理由」を書いて「差戻し」を押します。差し戻された配信は、配信担当が直して保存し、もう一度申請します。

承認済みの配信の範囲だけを変えるときは、管理者か承認者が次の手順で行います。承認が必要な組織では、申請者とは別の人が行います。内容は変わりません。

1. 「承認の範囲」を直します。
2. 「固定した内容を確認しました」にチェックを入れます。
3. 「範囲を変えて承認し直す」を押します。

**確認すること**：「承認済み：」の表示が、新しい範囲に変わったこと。

### 5.5 配信方法を選ぶ

配信の日時は、**承認済みになってから**選びます。下書きや承認待ちの間は、予約できません。

| 配信方法 | 操作 |
|---|---|
| 今すぐ送る | 「配信方法」で「配信開始を押したら送る」を選びます。内容を確かめて「配信開始」を押します |
| 予約する | 「予約」を選び、日本時間の日時を入力して「予約する」を押します。日時は5分後から90日後まで選べます。確定したら「予約済み」の表示と日時を確かめます |
| 予約を変える | 「予約の取消」を押して承認済みに戻します。取り消しが終わったことを確かめてから、日時を選び直して予約します |

**「配信開始」や「予約する」を押すと、確認の画面は出ずにそのまま進みます。** 押す前に、内容、配信リスト、配信方法、日時を確かめてください。

- 最初に表示される日時のまま確定せず、日付と時刻を確かめてください。
- 今すぐ送るなら今の時刻が、予約するなら予約の日時が、承認の範囲の期間に入っている必要があります。外れていると、「承認された送信期間の範囲外です。期間内の日時を指定してください。」と表示されます。
- 毎時0分は受信側が混み合います。5分などにずらすと、混雑を避けられます。
- 予約した時刻は、最も早く始まる時刻です。ほかの配信が送信中のときは、その配信が終わるまで待ちます。予約した時刻は、全員に届く時刻ではありません。
- 予約した時刻から15分たっても始まらないときは、管理者に通知が届きます。
- 確定した配信と予約は、ブラウザを閉じてもサーバーで進みます。

## 6. 配信の結果、停止、要確認

この節では、配信の結果の読み方と、止め方、止まったときの対応を説明します。

### 6.1 結果を見る

「配信履歴」で配信リストか件名を押すと、詳しい内容が開きます。配信状況は10秒ごとに更新されます。配送の結果は、数分遅れて反映されます。

| 表示 | 意味と、次にすること |
|---|---|
| 送信済み（SES受付） | SESが送信を受け付けた数です。受信トレイに届いた数ではありません |
| 配送 | 相手のメールサーバーが受け取った数です。開封や受信トレイへの到着とは別です |
| 失敗・不明 | 詳しい一覧を確かめてください。「不明」は届いている可能性があります。自動では送り直しません（6.4節） |
| 停止済みのため送らなかった | 送信の直前に、配信停止や完全削除が分かったため、送らなかった数です。失敗の数には含めません。1日に送れる件数には数えられる場合があります |
| 送信期限 | 「送信期限：○・未送信 ○件」と表示されます。期限を過ぎると、残りは送りません |
| 配送記録 | 配送の記録が届いているかの点検結果です。「件数が少ないため判定していません」は、正常という意味ではありません |
| 完了 | 配信の処理が終わった状態です。全員に届いたという意味ではありません。失敗、不明、配送の状況を確かめてください |
| 一時停止 | 止まった理由を確かめてください。自分たちで止めた場合は、権限のあるスタッフが再開できます。システムが止めた場合は、管理者に連絡してください |
| 要確認 | 管理者が記録を調べる必要があります。新しい配信を作って送り直さないでください（6.5節） |
| 結果不明の調査 | 「不明」の宛先があると表示されます。管理者が調べて、判断を記録します（6.4節） |

以前の記録では、停止済みのため送らなかった宛先が「失敗」（コード `CONTACT_BLOCKED`）と表示されていることがあります。

### 6.2 止める

1. 間違いに気づいたら、その配信を開いて「一時停止」を押します。
2. 管理者に連絡します。
3. 残りを送らないと決めたら「中止」を押します。
4. 確認の画面で「確定する」を押します。中止した配信は再開できません。

**確認すること**：状態が「一時停止中」または「中止」になったこと。

**SESがすでに受け付けたメールは、一時停止や中止をしても取り消せません。**

- 一時停止を受け付けた後は、新しい送信を始めません。そのときSESへ送っている途中の1通は、止められません。
- 一時停止のまま7日たつと、自動で中止になります。
- 1日の上限に達して待っているときは、再開の予定時刻が表示されます。ただし、認証や送信枠などに問題があれば、続きは送られません。
- システムが止めた配信は、管理者が原因を直してから再開します。再開するときは、「原因・是正内容・少量での再確認」と「確認の証跡（delivery-checks/ から始まる保存先）」を入力します。手順は[運用手順書](運用手順書.md)にあります。

### 6.3 承認の範囲や期限のために止まったとき

承認の範囲から外れる配信は、HT2が自動で止めます。表示ごとの対応は次のとおりです。

| 画面の表示 | 起きたこと | すること |
|---|---|---|
| 「宛先が承認の最大件数を超えたため、送らずに承認待ちへ戻りました。」 | 送信の準備で数えた宛先が、最大件数より多かった。1通も送っていません | 承認者か管理者が、範囲を見直して承認し直します。内容は固定されたままです。そのあと配信担当が、もう一度開始します |
| 「この配信は期限までに送り終えられません。」 | 送信期限までに送り終えられない見込みです。1通も送っていません | 管理者に1日の上限の引き上げを頼みます。または、承認者が送信期限を延ばして、承認し直します（5.4節） |
| 「承認された送信期間の範囲外です。」 | 今の時刻か予約の日時が、承認した期間の外です | 期間内の日時を選び直します。期間を変えるときは、承認し直します |
| 「送信期限を過ぎたため中止しました。未送信 ○件。」 | 送信中に送信期限になりました。残りは送っていません | 未送信の件数を確かめ、管理者に連絡します |
| 「予約日時から15分を過ぎても始まらなかったため、管理者へ通知しました。」 | ほかの配信の終了待ちなどで、予約が遅れています | 管理者が、ほかの配信の状況を確かめます。送信期限までに始まらなければ、送らずに中止します |

- 承認を不要にしている組織でも、最大件数を超えたときは承認し直しが必要です。
- 送信期限で中止した配信の続きを、新しい配信で送らないでください。新しい配信は、すでに送った会員にも届きます。

### 6.4 結果不明の調査（管理者）

「不明」は、SESが受け付けたかどうか分からない宛先です。届いている可能性があるため、HT2は自動で送り直しません。不明の宛先がある配信には、「結果不明の調査」が表示されます。

管理者は、次の手順で調べて、判断を記録します。

1. 配信を開き、「失敗・不明・停止済みの宛先」で不明の宛先を確かめます。
2. 「結果不明の調査」で、「SES の受付を確認」の件数を見ます。
3. 必要なら、宛先ごとの配送の記録を確かめます（4.9節）。
4. 「判断」で、「調査を継続」か「送り直さず調査を終了」を選びます。
5. 「調べた内容・判断の根拠」を書きます。500文字以内です。
6. 「判断を記録」を押します。

**確認すること**：判断の一覧に、日時、担当者、判断、根拠が追加されたこと。

- 結果不明の調査には、送り直す選択肢はありません。
- 配送の記録にSESの受付が見つからなくても、受け付けていない証拠にはなりません。
- 元のアドレスは、管理者だけが確かめられます。確かめられるのは、配信の開始から30日以内で、調査中の間だけです。
- 調査を終了すると、保存していた宛先の一覧は消えます。
- 根拠の中のアドレスやURLは、伏せ字にして保存されます。
- 調査が3日を過ぎても終わらないと、通知が届きます。その後は、7日に1回まで通知します。

### 6.5 要確認になったとき（管理者）

「要確認」は、処理が途中で止まり、送ったかどうか分からない宛先がある状態です。対象は最大20件です。管理者が、「要確認：管理者の判断が必要です」の欄で判断します。

| 判断 | 結果 |
|---|---|
| 中止 | 残りは送りません。中止した配信は再開できません |
| 飛ばして再開 | 該当の宛先に届かない可能性があります（最大20件） |
| 送り直して再開 | 該当の宛先に二重に届く可能性があります（最大20件） |
| 最初からやり直す | 宛先を確定する途中で止まったときだけ選べます。まだ送信は始まっていません |

1. 配送の記録を確かめます。手順は[運用手順書](運用手順書.md)にあります。
2. 「判断」を選びます。
3. 「確認した内容・判断の理由」を書きます。
4. 「判断を確定」を押し、確認の画面で「確定する」を押します。

**確認すること**：配信の状態が、選んだ判断のとおりに変わったこと。

**データを復元した後の要確認**：AWSの管理者がデータを復元すると、途中だった配信は「要確認」になります。この場合は、「中止」だけを選べます。復元した進捗からは再開できません。送り直す場合は、新しい配信として作り直します。このとき、二重に届く可能性があります。

## 7. 困ったとき

画面には日本語の説明が表示されます。取得できたときは「問い合わせ番号」も表示されます。英語のエラーコードを調べる必要はありません。表示とコードの対応は、運営画面の「使い方」にも一覧があります。

| 画面の表示や症状 | すること |
|---|---|
| 「他の人が先に操作しました」 | 入力した内容を控えます。「読み込み直す」で最新の状態を確かめてから、もう一度操作します |
| 「通信結果を確認できません」「処理を完了できませんでした」 | 同じ操作を繰り返さないでください。読み込み直して、配信や取込の結果を確かめます。判断できなければ管理者に連絡します |
| 「テスト送信先の登録と、配信リストの購読を確認してください」 | テスト送信先の登録と購読の状態を確かめるよう、管理者に頼みます |
| 「受信確認の記録がない、または期限切れ・設定変更で無効です」 | 管理者が8.3節の手順で受入確認をやり直します。それまで一般の配信は止めておきます |
| 「全体の停止スイッチが入っています」「送信元ドメインの認証に異常があります」 | AWSの管理者に連絡します。配信を作り直して避けようとしないでください |
| 「設定を変更したため、送信元の確認をやり直しています。数分後にもう一度お試しください。」 | 組織設定を保存した直後です。送信元の確認が自動でやり直されています。数分待ってから、もう一度操作します。長く続くときは、AWS の管理者に連絡します |
| 「SESの24時間の送信枠が足りません」 | 管理者に連絡して、枠が戻るのを待ちます。日付が変わっても戻るとは限りません |
| 「開始処理を作成できませんでした。配信は承認済みに戻っています。」「予約を作成できませんでした。配信は承認済みに戻っています。」 | 原因を直してから、もう一度開始か予約をします |
| 「要確認：開始処理の有無を確認できません」「要確認：予約の有無を確認できません」 | 同じ操作を繰り返したり、別の配信を作ったりしないでください。管理者に連絡します。管理者が、実行と予約と送信の履歴を確かめます |
| 「この配信は期限までに送り終えられません。」 | 1通も送っていません。6.3節に従って、上限の引き上げを頼むか、期限を延ばして承認し直します |
| 「宛先が承認の最大件数を超えたため、送らずに承認待ちへ戻りました。」 | 1通も送っていません。承認者か管理者が、範囲を見直して承認し直します |
| 「承認された送信期間の範囲外です。」 | 承認した期間の中の日時を選び直します |
| 「送信期限を過ぎたため、残りを送らずに中止しました。」 | 未送信の件数を確かめ、管理者に連絡します |
| 「予約日時から15分を過ぎても開始していません。」 | 管理者が、ほかの配信の状況を確かめます |
| 「受付件数に対して配送の記録が不足しています。」「配送の記録が届いていません。」 | 配信は止まっています。管理者が記録を確かめ、AWSの管理者と原因を直します |
| 「結果不明の調査が3日を過ぎています。」 | 管理者が6.4節の手順で調べ、判断を記録します |
| 「準備状況を取得できません。」 | AWSの管理者に、システムの状態を確かめるよう頼みます |
| 「同意の取得経路にはメールアドレスを含めず、申込方法などを記入してください。」 | 経路の欄から、アドレスを消します。「会員申込フォーム」のように書き直します |
| 「宛先の登録・取込を処理中です。終わるまでお待ちください。」 | 取込や一括更新の反映が終わるまで待ちます |
| 取込の状態が「確認の期限切れ」になった | 24時間以内に反映しなかったため、ファイルは消えました。もう一度ファイルを送ります |
| 「完全削除の記録を確認できません。」 | 登録、CSV取込、購読の再開はできません。AWSの管理者に連絡します |
| 「スタッフを変更するには、ログアウトしてからログインし直してください。」 | 画面はログアウトします。ログインし直してから、15分以内に変更します |
| 「自分自身のアカウントは変更できません。」 | 別の管理者に頼みます |
| 「有効な管理者を0人にはできません。」 | 一覧を読み直します。先に、別の管理者を追加します |
| 「検査を始めた後に送信設定かDNSが変わりました。」 | 新しい受入検査を始めます（8.2節） |
| 「この記録の形式に対応していません。」 | AWSの管理者に、実行環境とプログラムの版を確かめるよう頼みます |
| 「復元の点検で要確認になった配信です。」 | 管理者が「中止」を選びます（6.5節） |
| ログインできない、役割がない | 自分のアカウントと役割を確かめるよう、管理者に頼みます |

連絡するときは、次の情報を伝えてください。

- 起きた日時
- 環境（本番か練習用か）
- 配信IDまたは取込ID
- 押したボタン
- 画面の説明と問い合わせ番号

パスワード、認証コード、トークン、会員名簿、配信停止のURLは、ふだんのチャットやスクリーンショットに含めないでください。

会員から「メールが届かない」と問い合わせがあったときは、管理者が購読、抑止、配送の記録を調べます（4.9節）。会員には、迷惑メールフォルダーと受信設定も確かめてもらいます。届かなかったと思い込んで、同じメールを送り直さないでください。

## 8. 管理者の設定と受入確認

この節では、管理者が「設定」で行う組織の設定と、受入確認の進め方を説明します。

### 8.1 組織の設定

管理者は「設定」の「組織設定」で次の項目を登録し、「設定を保存」を押します。

- 差出人の名前
- 差出人アドレスの `@` より前の部分
- 返信先
- 発行者の名前、所在地、問い合わせ先
- 承認が必要かどうか（不要にできるのは、スタッフが1人だけの組織です）
- 送信の速さ
- テスト送信先（最大5件）。先に「宛先」で登録したアドレスだけを設定できます。初めて保存するときは空のままにしてください

設定を保存すると、送信元の確認が自動でやり直されます。終わるまでの数分間は、テスト送信や配信の開始ができません。

次の項目は、AWSの管理者が担当します。

- 送信元のドメイン
- 1日に送れる上限
- 全体の停止スイッチ
- 配信リストの追加と名前の変更
- 抑止の解除

スタッフのアカウントと役割は、管理者が「スタッフ」で管理します（9節）。

管理者は、「設定」の「監査ログ」で、月ごとの操作の記録を見られます。「対象月（UTC）」を選んで「表示」を押します。

### 8.2 受入確認を進める

受入確認は、主要なメール事業者で正しく受信できることを確かめ、その記録を残す作業です。本番では、有効な受入記録がないと配信を始められません。「設定」の「受入確認」で、画面の案内に沿って「始める」「試験を記録する」「証跡を登録する」「確定する」の順に進めます。

確認値や保存先を、手で書き写す必要はありません。確認値は、HT2が自動で計算します。試験の内容は、[構築手順書](構築手順書.md)の6節にあります。実際の受信の試験は、AWSの管理者と一緒に行います。

1. 「新しい受入検査を始める」を押します。検査は30日以内に確定してください。
2. 「進行中の検査」で、始めた検査を選びます。
3. 「2. 試験を記録する」で、「試験」を選びます。
4. 試験を行い、「結果」と「確認内容」を入れて、「試験結果を記録」を押します。すべての必須試験について、手順3と手順4を繰り返します。
5. 「3. 証跡を登録する」で「試験」を選び、「証跡ファイル」を選んで「証跡を登録」を押します。試験ごとに証跡を登録します。
6. 試験の表で、すべての必須試験が「合格」で、証跡が1件以上あることを確かめます。
7. 「4. 確定する」の「確定の確認内容」を書き、「受入検査を確定」を押します。
8. 確認の画面で「確定する」を押します。

**確認すること**：「受入確認」の表示が、「合格／有効期限 …／残り○日」になったこと。

- 証跡のファイルは、1つ1MiB以下です。メールの原文などの証跡は、通常の画面には表示されません。
- 「対象外」は、必須の試験には使えません。
- 不合格の必須試験があるまま確定すると、不合格として記録されます。一般の配信は止まります。
- 検査を始めた後に送信の設定かDNSが変わると、確定できません。「検査を始めた後に送信設定かDNSが変わりました。新しい受入検査を始めてください。」と表示されたら、新しい検査を始めます。

### 8.3 受入記録の期限と、やり直し

受入記録が有効なのは、確定から90日以内で、送信の設定とDNSが確定したときと同じ間だけです。残りの日数と、無効になった理由は、「受入確認」に表示されます。

期限の30日前、14日前、7日前、1日前と、期限が切れたときに、通知が届きます。最初の通知が届いたら、受入確認を始めてください。

| 無効になった理由の表示 | すること |
|---|---|
| 確認から90日を過ぎたため | 新しい検査を始めます |
| 送信の設定かプログラムが変わったため | AWSの管理者に変更の内容を確かめてから、新しい検査を始めます |
| DNSの設定が変わったため | 表示された項目について、AWSの管理者がDNSを確かめます。そのあと、新しい検査を始めます |
| 送信元の認証の確認で問題が見つかったため | AWSの管理者が認証を直してから、新しい検査を始めます |

やり直しでは、テスト送信を「受入確認の再検証」として送ります。手順は次のとおりです。

1. 原因を直します。AWSの管理者が、DNS、認証、監視を確かめます。受入に合格するまで、一般の配信は始めないでください。
2. 「設定」で、新しい受入検査を始めます（8.2節の手順1）。
3. 保存済みのテスト用の配信を開きます。
4. 「受入確認を再検証する」にチェックを入れます。
5. 「再検証の理由」を書き、その下で、手順2で始めた検査を選びます。
6. 「テスト送信」を押し、確認の画面で「確定する」を押します。送り先は、設定済みの最大5件だけです。
7. 8.2節の手順3から手順8で、試験の結果と証跡を登録して、確定します。

**確認すること**：「設定」の「復旧のテスト送信の結果」に、送った日時と結果が残ったこと。合格の記録を確かめてから、少ない件数で配信を始めます。

- 認証、送信枠、抑止などの通常の確認は、このテスト送信でも行われます。
- テスト送信が成功しただけでは、一般の配信はできるようになりません。
- 実際の受信の試験と証跡の集め方は、AWSの管理者が[構築手順書](構築手順書.md)に従って行います。障害への対応や連絡先の復元は、[運用手順書](運用手順書.md)を見てください。

## 9. スタッフを管理する（管理者）

「スタッフ」の画面は、管理者だけに表示されます。スタッフの追加、役割の変更、無効化と有効化、認証アプリの初期化、パスワードの再設定ができます。

**変更は、ログインから15分以内に行います。** 15分を過ぎて変更しようとすると、「スタッフを変更するには、ログアウトしてからログインし直してください。」と表示され、画面はログアウトします。ログインし直してから、もう一度操作します。

### 9.1 スタッフを追加する

1. 「スタッフ」を開きます。
2. 「スタッフを追加」に、「メールアドレス」と「名前」を入れます。
3. 「役割（複数選択可）」で役割を選びます。
4. 「追加して案内メールを送る」を押します。

**確認すること**：「スタッフ一覧」に、追加した人が「有効／初回ログイン待ち」と表示されたこと。

追加した人には、仮パスワードの案内メールが届きます。その人は、2.1節の手順でログインします。

### 9.2 役割を変える・無効にする

1. 「スタッフ一覧」で、対象の人の行を探します。
2. 操作のボタンを押します（下の表）。
3. 確認の画面で内容を確かめ、「確定する」を押します。

**確認すること**：「スタッフの変更を保存しました。役割は60秒以内に反映されます。」と表示され、一覧が変わったこと。

| したいこと | 操作 |
|---|---|
| 役割を変える | 役割を選び直して、「役割を保存」を押します |
| 辞めた人の権限を外す | 「無効化」を押します |
| 無効にした人を戻す | 「有効化」を押します |
| 認証アプリを入れた端末をなくした | 「認証アプリを初期化」を押します。その人は、次のログインで登録し直します |
| パスワードを忘れた | 「パスワードを再設定」を押します |

- 変更は監査ログに残り、運営の通知先にも知らされます。
- 無効にした人は、60秒以内に操作できなくなります。
- 自分自身のアカウントは変更できません。別の管理者に頼みます。
- 「認証アプリを初期化」が実際の AWS で期待どおりに動くかは、まだ確かめていません。次のログインで登録の案内が出ないときは、AWSの管理者に相談してください。その人を無効にして、新しいアカウントを作る方法があります。

### 9.3 管理者が1人になるとき

管理者は、2人以上にしてください。有効な管理者が1人以下のときは、「有効な管理者が1人以下です。管理者を2人以上にしてください。」と表示されます。

- 有効な管理者が1人になる変更では、警告の確認画面が出ます。その1人がログインできなくなると、AWSの管理者による復旧が必要になります。内容を確かめてから、「確定する」を押します。
- 辞めた管理者の権限は、この確認をすればすぐに外せます。
- 有効な管理者を0人にする変更はできません。
- 管理者を減らす前に、新しい管理者を追加します。その人が初回のログインを済ませたことを確かめてから、減らします。

### 9.4 変更の結果が分からないとき

通信の問題などで変更の結果が分からないときは、「一覧で結果を確かめてください。変更ロックは5分で失効します。」と表示されます。

1. 同じ操作を繰り返さないでください。
2. 「一覧で結果を確かめる」を押します。
3. 一覧で、変更が反映されたかを確かめます。
4. 反映されていなければ、5分たってから、必要な変更だけをもう一度行います。

**確認すること**：一覧の役割と状態が、意図したとおりになったこと。
