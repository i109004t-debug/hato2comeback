# Postline 利用者操作手順書

Postlineの運営画面で、宛先登録・メール作成・承認・配信結果の確認をするスタッフ向けの現行手順書です。設計時の「Postline 利用者向けご案内 v0.1」に代わり、こちらを使ってください。

通常のスタッフはAWSへの契約・登録やCLIの準備は不要です。ブラウザ、管理者が発行した個人のアカウント、MFA用の認証アプリを用意します。AWS管理者向けの初期準備は[AWS導入手順書](AWS導入手順書.md)にあります。

## 1. 最初に受け取る情報

導入担当者は、次の表を実値で埋めた写しをスタッフへ渡してください。このリポジトリには特定の組織の稼働URLや問い合わせ先は登録していません。

| 項目 | 導入担当者の記入欄 |
|---|---|
| 組織名・本番運営画面URL | 未記入 |
| 練習用運営画面URL・使ってよい宛先 | 未記入。本番会員を練習に使わない |
| あなたの役割・初回ログインの案内先 | 未記入。パスワードはこの表に書かない |
| Postline管理者・通常の連絡方法 | 未記入 |
| 障害時・時間外の連絡方法 | 未記入 |
| 承認を依頼する相手と連絡方法 | 未記入 |
| 配信リストの表示名・CSV用の内部名 | 未記入。例：会報 / kaiho |
| 差出人名・アドレス、返信の受信担当 | 未記入 |
| テスト送信先・1日上限・配信する時間帯 | 未記入 |
| 受入確認の次回期限と担当者 | 未記入 |

AWS管理者は構築後にURL・アカウント・役割と、テスト送信の確認結果を引き渡します。Postline管理者は利用者ごとに、この表と最初のログインが使えることを確認してください。

## 2. ログインと役割

1. 渡された運営画面URLを開き、「ログイン」を押します。メールで届いた初回案内のユーザー名・仮パスワードを入力します。
2. 初回は自分のパスワードへ変更し、画面の案内に従って認証アプリを登録します。表示されたコードを入力してMFAを完了します。
3. 画面上部の名前・環境を確認します。本番と練習用を取り違えないよう、ブックマークの名前も分けます。
4. 作業を終えるときは「ログアウト」を押します。共有端末に認証情報を保存しないでください。

初回案内が期限切れ、パスワードを忘れた、認証端末をなくした場合は表の管理者へ連絡します。本人確認後にAWS管理者がCognitoで対応します。アカウントや認証コードを他のスタッフと共用しないでください。

| 役割 | 主にできること |
|---|---|
| 管理者（admin） | 組織設定、宛先登録、配信、承認、再受入、購読の再開、完全削除、要確認の判断 |
| 配信担当（sender） | 宛先登録・CSV取込、下書き、テスト送信、承認申請、配信開始・予約 |
| 承認者（approver） | 申請内容の承認・差戻し、配信の一時停止・中止 |
| 閲覧者（viewer） | 配信結果と宛先の閲覧。アドレスは一部を伏せて表示 |

申請者本人は、管理者でも自分の申請を承認できません。利用者の追加・役割変更はAWS管理者へ依頼します。ボタンが無効のときは、その近くの説明を確認してください。

## 3. 最初の1通を送る流れ

1. 管理者が「設定」で差出人・法定表示・テスト送信先を確認します。テスト先は宛先に登録され、対象の配信リストを購読している必要があります。
2. 配信担当が「配信」→「新しい配信を作成」を開き、配信リスト、件名、本文を入力して「下書き保存」を押します。
3. 「プレビュー」で本文・リンク・自動フッターを確認し、「テスト送信」を押します。テスト先で受信、表示、返信先を確認します。
4. 修正があれば保存・確認をやり直し、「承認申請」を押します。承認者へ配信IDと確認依頼を連絡します。
5. 別の承認者が「配信履歴」から開き、固定された内容を確認して承認します。
6. 配信担当が承認済みの画面を開き、配信方法を選んで開始または予約します。承認だけでは送信されません。
7. 「配信状況」で終了まで見届け、「失敗」「不明」と配送結果も確認します。

スタッフ1人の組織で管理者が承認不要に設定した場合は、申請後に承認済みになります。その場合は手順5を省き、配信方法を確認して開始します。

本番の初回は、AWS管理者とPostline管理者による受入試験の合格後に進めます。一般会員を使って受入試験を代用しないでください。

## 4. 宛先を登録・変更する

「宛先」でメールアドレスを完全一致検索すると、名前・配信リスト・同意・全停止・配送抑止を確認できます。部分一致検索はありません。配信リストと購読状態で絞り込み、50件ごとに「次へ」で移動できます。

新規登録では、メールアドレス、任意の名前、本人が同意した配信リスト、同意日時と取得経路を入力します。取得経路には、例えば「会員申込フォーム」のように後で確認できる内容を記録し、実際の同意を確認せず登録しないでください。操作を「新規登録」にして「実行」を押し、検索結果を確認します。

変更・停止では、先に検索して現在の状態を確認します。名前の訂正は名前だけ変更します。退会の連絡は「全停止（退会）」、1種類だけ止める場合はその配信リストを1つ選んで「選んだ配信リストの停止」を実行します。既存宛先への新しい配信リストの追加も管理者の新しい同意確認が必要です。停止を通常の編集やCSVで戻そうとしないでください。

「購読の再開」は管理者が新しい同意の日時・取得経路・理由を確認して扱います。**今回、本人が同意した配信リストをすべて選びます。選ばなかった配信リストは停止になります。** 通常の編集ではSESの解除状態を上書きしません。再開の結果が不明、同時に停止があった場合は停止を維持し、管理者からAWS運用担当へ引き継ぎます。「完全削除」は今後の再登録・CSV取込もできなくなる操作です。退会だけの場合は全停止を使ってください。

「配送しない宛先（抑止）」は、バウンスや苦情により配送対象から除かれている状態です。購読の同意があっても抑止は自動解除されません。新しい宛先で作り直して回避せず、管理者へ連絡してください。

### CSVでまとめて登録する

UTF-8、2MiB以下、20,000データ行以下のCSVを使います。Excel等から保存する場合は「CSV UTF-8」を選びます。列の意味は次のとおりです。

| 列 | 内容 |
|---|---|
| email | メールアドレス。必須 |
| name | 名前。任意、50文字以内 |
| consent_at | 実際の同意日時。時差付きの日時。例 `2026-10-01T10:00:00+09:00` |
| consent_source | 同意の取得経路。必須、100文字以内 |
| consent_version | 同意した案内文の版。任意、30文字以内 |
| topics | 配信リストの内部名。複数は `;` 区切り。表示名を入れない |

```csv
email,name,consent_at,consent_source,consent_version,topics
member1@example.jp,山田太郎,2026-10-01T10:00:00+09:00,会員申込フォーム,v1,kaiho
member2@example.jp,鈴木花子,2026-10-02T11:30:00+09:00,会員申込フォーム,v1,kaiho;event
```

例の宛先をそのまま取り込まず、自組織の同意済みデータと内部名に置き換えます。日時は未来にせず、名前等にカンマ・改行・引用符がある場合はCSVの引用規則で保存します。

1. 「宛先」→「CSV取込」でファイルを選び、「取り込む」を1回押します。
2. 取込IDを控え、取込履歴の「結果を表示」で終了を確認します。画面は処理中に更新されます。
3. 登録対象・処理済み・登録失敗・登録しなかった行を確認します。行番号は見出しを含む番号です。
4. 完了後、少数を検索し、同意と配信リストが合っているか確認します。

CSVは新しい宛先だけを登録します。既存宛先・完全削除済み宛先・重複等は結果に理由が表示されます。名簿の更新・再同意には使いません。「要確認」や通信結果不明の場合は、同じファイルを再投入せず取込IDを管理者へ渡します。

## 5. 作成、テスト、承認、予約

本文はテキストのみで50KiB以下、件名は200文字以内です。件名・本文に `{{` と `}}` は使えません。添付ファイルや画像の挿入はありません。案内先は公式URLを使い、短縮URLや別の送り手を装う差出人・件名を避けます。発行者・所在地・問い合わせ先と解除案内のフッターは自動で付きます。

「テスト送信」は「設定」にある最大5件だけへ送ります。下書きを保存してから実行してください。日次上限にも数えられます。表示はプレビューだけでなく実際のメールでも確認し、解除試験はテスト専用の宛先で行います。結果が不明なら連打しません。

「承認申請」で本文・件名・差出人・フッターが固定されます。承認者は「固定した内容の確認」を読み、「固定した内容を確認しました」にチェックして「承認」を押します。訂正が必要なら理由を書いて「差戻し」。配信担当は差戻し後に修正・保存・再申請します。

配信日時は**承認済みになってから**選びます。下書きや承認待ちでは予約設定はできません。

| 配信方法 | 操作と確認 |
|---|---|
| 今すぐ | 「配信方法」で「配信開始を押したら送る」を選び、内容を確認して「配信開始」。押すと開始処理へ進む |
| 予約 | 「予約」を選び、日本時間の日時を入力して「予約する」。5分後〜90日後を指定。確定後に「予約済み」と表示日時を確認 |
| 予約の変更 | 「予約の取消」で承認済みに戻し、日時を選び直して再予約。取消の完了を確認してから進む |

初期表示の日時をそのまま信用せず、確定前後に日付・時刻・配信方法を確認します。00分を避けて05分などを選ぶと、毎正時の混雑を避けられます。別の配信が送信中なら待機するため、予約時刻は全件到着時刻ではありません。ブラウザを閉じても、確定した配信・予約はサーバーで動きます。

「配信開始」「予約する」を押した後に、別の確認画面は出ません。押す前に内容・宛先の配信リスト・配信方法・日時を確認してください。

## 6. 配信結果、停止、要確認

「配信履歴」で配信リスト・件名を押すと詳細へ進みます。配信状況は10秒ごとに更新され、配送イベントには数分の遅れがあります。

| 表示 | 意味と次の操作 |
|---|---|
| 送信済み（SES受付） | SESが送信処理を受け付けた数。受信トレイ到達数ではない |
| 配送 | 相手側のメールサーバーが受領した数。開封や受信トレイ到達とは別 |
| 失敗・不明 | 詳細一覧を確認。不明は送れた可能性があり、自動では送り直さない |
| 完了 | 配信処理が終了した状態。全員へ届いた意味ではない。失敗・不明・配送状況を確認 |
| 一時停止 | 停止理由を確認。自分で止めた場合は権限のあるスタッフが再開可能。システム停止は管理者へ連絡 |
| 要確認 | 管理者が記録を調べる必要がある。新しい配信を作り直して再送しない |

誤りに気付いたら対象の配信を開き、「一時停止」を押して管理者へ連絡します。残りを送らないと決めたときは「中止」。中止した配信は再開できません。SESが既に受け付けたメールは一時停止・中止でも取り消せません。

一時停止から7日で自動中止になります。日次上限による待機では再開予定が表示されますが、認証や送信枠等が不健全なら続行しません。「要確認」の再送判断やシステム停止からの再開は、管理者が[運用手順書](運用手順書.md)に従います。

## 7. 困ったとき

画面には日本語の説明と、取得できた場合は「問い合わせ番号」が表示されます。内部の英語エラーコードを探す必要はありません。

| 表示・症状 | 操作 |
|---|---|
| 「他の人が先に操作しました」 | 入力を控え、「読み込み直す」で最新状態を確認してから操作 |
| 「通信結果を確認できません」「処理を完了できませんでした」 | 同じ操作を繰り返さず、読み込み直して配信・取込結果を確認。判断できなければ管理者へ |
| 「テスト送信先の登録と、配信リストの購読を確認してください」 | 管理者にテスト先と購読状態の確認を依頼 |
| 「受信確認の記録がない、または期限切れ・設定変更で無効です」 | 管理者が8節の再受入を実施。一般配信は止めたまま |
| 「全体の停止スイッチが入っています」「送信元ドメインの認証に異常があります」 | AWS管理者へ連絡。配信を作り直して回避しない |
| 「SESの24時間の送信枠が足りません」 | 管理者へ連絡し、枠の回復を待つ。日付変更だけで回復するとは限らない |
| ログインできない・役割がない | 管理者に本人のアカウント・役割を確認してもらう |

連絡時は、発生日時、環境、配信IDまたは取込ID、押したボタン、画面の説明と問い合わせ番号を渡します。パスワード・認証コード・トークン・会員名簿・解除URLを通常のチャットやスクリーンショットに含めないでください。

「メールが届かない」という会員の問い合わせは、管理者が購読・抑止・配送結果を調べます。迷惑メールフォルダーや受信設定も確認してもらいます。届かなかったと推測して同じメールを再送しないでください。

## 8. 管理者の設定と受入確認

「設定」で差出人名、差出人アドレスの@より前、返信先、発行者の名称・所在地・問い合わせ先、承認要否、速度、最大5件のテスト送信先を登録します。ドメイン、日次上限、全体停止スイッチ、スタッフの権限はAWS管理者の担当です。承認を不要にできるのはスタッフが1人だけの組織です。

受入記録は90日以内で現在の設定と一致する必要があります。期限切れ、不合格、送信元・DNS・送信コード等の変更時は、AWS管理者と組んで確認をやり直します。

1. 原因を直し、AWS管理者がDNS・認証・監視を確認します。一般配信は受入合格まで開始しません。
2. 管理者が保存済みのテスト用配信を開き、「受入確認を再検証する」を選択し、「再検証の理由」を記入して「テスト送信」。送信先は設定済みの最大5件に限定されます。通常の認証・送信枠・抑止等の検査は継続します。
3. [構築手順書](構築手順書.md)6節の試験と証跡をそろえます。AWS管理者から、実在する証跡キー、送信設定の確認値、DNS設定の確認値、試験結果を受け取ります。確認値を自分で作らないでください。
4. 「設定」→「受信確認の記録」で確認結果、内容、証跡、2つの確認値、全必須試験の結果を入力し、「受信確認の記録を登録」を押します。
5. 合格の記録と最新設定を確認し、少量から配信します。不合格が残る場合は合格にしません。

テストが成功しただけでは一般配信は有効になりません。証跡の保存や実機試験はAWS管理者の[構築手順書](構築手順書.md)、障害対応・連絡先の復元は[運用手順書](運用手順書.md)を参照してください。
