# HT2 ご利用案内

**会報やお知らせを、配信に同意した会員へ。作成・承認・配信・結果の確認までを1つの画面で。**

| 項目 | 内容 |
|---|---|
| サービス名 | HT2 |
| 文書 | 利用者向けご案内・操作ガイド |
| 版 | v0.2（公開前案） |
| 改訂日 | 2026年11月3日 |
| 想定読者 | 配信組織の運営スタッフ（管理者・配信担当・承認者・閲覧者） |
| 対応する設計 | 基本設計書 v2.2、詳細設計書 v2.2 |
| 運営画面のURL | **導入時に、組織の管理者からお知らせします** |
| お問い合わせ先 | 組織内のHT2管理者（AWSの管理者） |

> **ご案内：HT2は現在、設計段階です。** この文書は提供予定の使い方を説明する案であり、現時点で実際のメール送信ができることを示すものではありません。画面の名称、上限の件数、しきい値などは、正式な運用開始までに変わることがあります。

## 1. HT2でできること

HT2は、ファンクラブなどの会員組織（以下「配信組織」）が、自分たちの独自ドメインから、配信に同意した会員へ会報やお知らせをまとめて届けるためのメール配信システムです。メールの送信にはAmazon SESを使い、配信停止やバウンス（届かなかったメール）の管理もSESの仕組みで行います。

- **宛先を管理**：会員のメールアドレスを1件ずつ登録するか、CSVファイルでまとめて取り込めます。
- **配信リストを使い分け**：「会報」「イベント案内」など、配信リスト（最大20）ごとに購読を管理します。
- **1画面で作成**：配信リスト・件名・本文を入力し、プレビューとテスト送信で確かめられます。
- **承認してから配信**：申請と承認を経て、すぐに配信するか、日時を指定して予約します。
- **結果を確認**：送信の受付、受信側への配送、バウンス、配信停止などの件数を確かめられます。
- **配信停止はSESが処理**：会員はメールの「登録解除」や本文のURLから、いつでも配信を止められます。

### 対象範囲

| 項目 | 内容 |
|---|---|
| 配信先 | メール事業者の制限なし（Gmail、Yahoo!メール、Outlook.com、iCloud、携帯キャリアメール、プロバイダメールなど） |
| 送信元 | 配信組織が管理する独自ドメイン1つと、その配下のアドレス（例：`info@fc.example.jp`） |
| 本文 | テキストメールだけ（日本語対応） |
| 宛先の登録 | 個別登録、CSV一括登録（新しい宛先だけ） |
| 配信方法 | 即時配信、予約配信（5分後から90日後まで） |
| 規模 | 1回の配信で最大10万件 |
| 対象外 | HTMLメール、差し込み（宛名の自動挿入）、添付ファイル、開封・クリックの計測、会員自身による登録フォーム、外部のアカウント（Amazonアカウント等）でのログイン |

> HT2は配信組織ごとに専用のAWSアカウントで動きます。複数の組織が1つの環境を共有することはありません。運営スタッフがAWSの画面を操作したり、アクセスキーを扱ったりする必要はありません。

## 2. 役割とできること

| 役割 | できること |
|---|---|
| 管理者 | 組織設定（差出人、法定表示、承認の要否、送信速度、テスト送信先）、停止した会員の購読の再開、完全削除、システムが止めた配信の再開、要確認の判断、監査ログの閲覧、その他すべて |
| 配信担当 | 宛先の登録・取込・配信停止、配信の作成・テスト送信・申請・開始・予約・一時停止・中止 |
| 承認者 | 配信の承認・差戻し・一時停止・中止 |
| 閲覧者 | 配信履歴と結果の閲覧（宛先のアドレスは一部を伏せて表示） |

- アカウントの作成・役割の変更・無効化は、AWSの管理者が行います。運営画面にはスタッフを管理する機能はありません。
- 申請した人は、その配信を自分で承認できません。
- 自分で止めた配信は、管理者・配信担当・承認者が再開できます。システムが自動で止めた配信を再開できるのは管理者だけです。

## 3. 使い始めるまで

### 3.1 管理者・AWSの管理者が行う準備

運営スタッフが配信を始める前に、組織の管理者とAWSの管理者が次の準備をします。

1. 配信組織用のAWSアカウントにHT2を構築し、配信リストを決めます。
2. 送信元ドメインのDNSに、SESが示す認証の設定（DKIM、MAIL FROM、SPF、DMARC）を登録します。
3. SESの本番利用を申請します。
4. 運営スタッフのアカウントを作り、役割を割り当てます。
5. 運営画面の「設定」で、組織設定（4章）を登録します。
6. 主要なメール事業者のテスト用アドレスで受信を確かめ、その結果を「受信確認の記録」として登録します。
7. 1日の送信上限を、少ない量から始める値に設定します。

**受信確認の記録がないと、本番の配信は始められません。** 記録の有効期限は90日です。送信元やDNSの設定を変えた場合も無効になり、確認をやり直す必要があります。

### 3.2 運営スタッフの初回ログイン

1. 招待メールに書かれたメールアドレスと仮パスワードで、運営画面にログインします（仮パスワードの有効期限は7日です）。
2. 新しいパスワードを設定します。12文字以上で、英大文字・英小文字・数字・記号をすべて含めてください。
3. スマートフォンの認証アプリ（ワンタイムパスワードを表示するアプリ）を登録します。**二要素認証は全員必須です。**
4. 次回からは、メールアドレス・パスワード・認証アプリのコードでログインします。

ログインの状態は最長8時間で切れます。パスワードを忘れた場合はログイン画面からメールで再設定できます。認証アプリを使えなくなった場合や、アカウントを止めたい場合は、AWSの管理者に連絡してください。

## 4. 組織設定（管理者）

「設定」画面で次を登録します。管理者以外は閲覧だけできます。

| 項目 | 内容 |
|---|---|
| 差出人 | 差出人名（1〜64文字）と、アドレスの `@` より前の部分。ドメインは構築時に決まった送信元ドメインに固定です |
| 返信先 | 任意。会員の返信を受け取れるアドレスにします |
| 法定表示 | 送信者の名称、所在地、問い合わせ先（メールアドレス・URL・電話番号のいずれか）。**未設定だと配信を申請できません** |
| 承認の要否 | 既定は「必要」。スタッフが1人だけの組織に限り、管理者が「不要」にできます（監査ログに残ります） |
| 送信速度の上限 | 1秒あたりの送信数。既定は毎秒10通です |
| テスト送信先 | 最大5件。宛先として登録済みで、配信リストを購読しているアドレスに限ります |

差出人・返信先・法定表示には、`{{` と `}}` を含めないでください。

## 5. 宛先を管理する

「宛先」画面で、会員のメールアドレスと購読状態を管理します。宛先の情報はSESの連絡先リストに保存されます。

### 5.1 個別に登録する

アドレス、名前（任意）、**同意の日時と取得経路**（例：入会申込フォーム）、同意した案内文の版（任意）、購読する配信リストを入力します。同意の日時と取得経路がない宛先は登録できません。

### 5.2 CSVでまとめて取り込む

**CSVで登録できるのは新しい宛先だけです。** すでに登録されているアドレスは、CSVに含まれていても変更されずに飛ばされます。配信を停止した会員がCSVの取込で購読に戻ることはありません。登録済みの宛先を変えるときは、画面から1件ずつ操作してください。

| 列名 | 必須 | 内容 |
|---|---|---|
| `email` | ○ | メールアドレス |
| `name` | 任意 | 名前（50文字まで） |
| `consent_at` | ○ | 会員が配信に同意した日時（ISO 8601形式。未来の日時は不可） |
| `consent_source` | ○ | 同意の取得経路や記録の所在（100文字まで。例：入会申込フォーム） |
| `consent_version` | 任意 | 同意した案内文の版など（30文字まで） |
| `topics` | ○ | 購読する配信リストの識別名。複数ならセミコロンで区切ります（例：`kaiho;event`）。識別名は管理者に確認してください |

先頭行は次のとおりです。

```csv
email,name,consent_at,consent_source,consent_version,topics
```

- 文字コードはUTF-8（BOM付きも可）、1ファイル2MiB以下・20,000行以下です。
- 日時の記入例は `2026-10-20T10:30:00+09:00` です。**実際に同意を得た相手の、実際の日時と取得経路**を書いてください。サンプルの値のまま取り込んだり、存在しない同意日時を作ったりしないでください。
- 上の表にない列があると、ファイル全体がエラーになります。
- 取込の結果は、件数と、行番号ごとの理由（ファイル内の重複、登録済み、削除済みのアドレス、形式の誤りなど）で表示されます。
- 取込の処理中は、個別登録と別の取込はできません。終わるまでお待ちください。

### 5.3 メールアドレスの扱い

- アドレスは小文字にそろえて登録します。使える文字は半角英数字と記号だけです。
- 先頭や末尾にドットがある、ドットが連続するなど、古い携帯電話のアドレスに見られる形式は、届かないおそれがあるため登録できません。
- Gmail（`gmail.com`・`googlemail.com`）は、アドレス中のドットや `+` 以降を除いた形で1件にまとめます。同じ受信箱に何通も届いたり、1つを停止しても別の表記に届き続けたりすることを防ぐためです。入力した表記も記録に残ります。

### 5.4 購読の変更・停止・再開・削除

| 操作 | できる人 | 内容 |
|---|---|---|
| 配信リストの追加 | 管理者、配信担当 | そのリストへの同意の記録が必要です |
| 配信リスト別の停止・全停止 | 管理者、配信担当 | 理由は監査ログに残ります |
| 購読の再開 | 管理者だけ | 一度停止した会員が改めて希望したときだけ。**新しい同意の証跡**（本人からの申込メールなど）が必要です |
| 完全削除 | 管理者だけ | 個人情報の削除請求があったときに、理由を入力して行います。削除したアドレスは、以後の登録や取込で受け付けません |

- 退会の連絡を受けたときは、全停止にしてください。アドレスと停止状態が残るので、誤って再び送ることを防げます。
- 宛先の検索はアドレスの完全一致だけです（部分一致の検索はできません）。
- 1件を表示すると、配送できないアドレスとしてSESに登録されているか（抑止の状態）と、その理由・日時を確認できます。

## 6. 配信を作成して開始する

### 6.1 配信画面

```text
┌──────────────────────────── HT2 ────────────────────────────┐
│ ○○ファンクラブ／ログイン中: 山田    [宛先] [配信履歴] [設定]       │
├───────────────────────────────────────────────────────────────────┤
│ 差出人      ○○ファンクラブ <info@fc.example.jp>   返信先 support@… │
│ 配信リスト  [会報 ▼]          購読者 約1,234件（前日時点）         │
│ 件名        [____________________________________________]       │
│ 本文        [                                            ]       │
│             [             テキスト本文                 ]       │
│ フッター    （自動）発行者・所在地・問合せ先・配信停止URL          │
│ 配信日時    (●) 承認後すぐ  ( ) 予約 [2026-12-01 19:05]           │
│ [プレビュー] [テスト送信] [下書き保存] [承認申請 / 配信開始]       │
├───────────────────────────────────────────────────────────────────┤
│ 配信状況    送信済○／失敗○／不明○ ・ 配送○／バウンス○／苦情○／停止○ │
│             [一時停止] [再開] [中止]                              │
└───────────────────────────────────────────────────────────────────┘
```

※ 設計段階のイメージです。件数は説明用の架空の数字です。

### 6.2 手順

| 手順 | 操作 | 担当 | 確認すること |
|---|---|---|---|
| 1 | 配信リストを選ぶ | 配信担当 | 購読者数の目安（前日時点） |
| 2 | 件名と本文を入力し、下書き保存 | 配信担当 | 誤字、日時、URL、連絡先 |
| 3 | プレビュー | 配信担当 | 本文の後ろに自動で付くフッター（法定表示と配信停止の案内） |
| 4 | テスト送信 | 配信担当 | 実際の受信画面での表示、配信停止のリンク |
| 5 | 承認申請 | 配信担当 | 申請した時点で件名・本文・フッターが固定されます |
| 6 | 承認または差戻し | 承認者（申請者以外） | 画面に表示される固定済みの内容 |
| 7 | 配信開始、または予約 | 配信担当 | 配信日時 |
| 8 | 配信状況の確認 | 全員 | 7章 |

- **入力の決まり**：件名は1〜200文字で、改行は入れられません。本文はテキストで50KiB以下です。件名・本文とも `{{` と `}}` は使えません。
- **フッター**：送信者の名称・所在地・問い合わせ先と配信停止のURLが、本文の後ろに自動で付きます。編集はできません。
- **短縮URL**：本文に短縮URLらしいリンクがあると注意が出ます。迷惑メールと判定されやすくなるため、使わないでください。
- **テスト送信**：送り先は、組織設定のテスト送信先（最大5件）だけです。テスト送信も1日の送信件数に数えます。他の配信の送信中はテスト送信できません。
- **差戻し**：理由を付けて下書きに戻ります。直して申請し直すと、新しい版として承認を受けます。
- **承認不要の設定**のときは、申請と同時に承認済みになります。

**承認された内容は、変更できません。** 直したいときは、その配信を中止し、新しい配信を作り直してください。

### 6.3 予約配信

- 予約できるのは5分後から90日後まで（日本時間）です。
- 毎正時（00分）は受信側が混み合い、遅延や受け取りの制限を受けやすくなるため、画面で注意が出ます。既定値は05分です。
- 予約は、開始されるまで取り消せます。
- 予約した時刻に別の配信が送信中なら、その配信が終わってから始まります。

### 6.4 配信の宛先

**宛先は、送信を始めた時点で配信リストを購読している会員です。** 承認や予約の後に配信を停止した会員には送りません。また、送る順番は配信ごとに混ぜ、同じメール事業者へ集中しにくくしています。

### 6.5 配信を開始できないとき

開始・予約の開始・再開のたびに、システムが送信の条件を確かめます。条件を満たさないと配信は始まらず、理由が画面に表示されます。予約した配信が開始時刻に条件を満たさなかった場合は「承認済み」に戻るので、原因を直してから開始し直してください。

| 表示される理由 | 意味 | 対応 |
|---|---|---|
| `SETTINGS_INCOMPLETE` | 法定表示などの組織設定が足りない | 管理者が設定する |
| `DELIVERY_CHECK_REQUIRED` | 受信確認の記録がない、または期限切れ・設定変更で無効 | 管理者が受信確認をやり直す |
| `AUTH_CHECK_FAILED` | 送信元ドメインの認証（DNS・SES）に異常がある | AWSの管理者がDNSとSESの状態を確かめる |
| `REPUTATION_ALARM` | バウンス率や苦情率が高く、警報が出ている | 原因を直し、警報が解除されるまで待つ |
| `QUOTA_INSUFFICIENT` | SESの24時間の送信枠が足りない | 枠が戻るのを待つ。いつも足りなければAWSの管理者が引上げを申請する |
| `SENDING_DISABLED`、`SES_PAUSED` | 全体の停止スイッチが入っている、またはSESが送信を止めている | AWSの管理者が理由を確かめる |
| `EVENT_DESTINATION_DISABLED`、`EVENT_LOG_STALE`、`MONITORING_UNAVAILABLE` など | 配送の記録や監視の仕組みが正しく動いていない | AWSの管理者が復旧する |
| `STATE_CONFLICT`、`VERSION_CONFLICT` | 他の人が先に操作した | 画面を読み込み直す |
| `HASH_MISMATCH` | 承認画面を開いた後に内容が変わった | 画面を読み込み直し、内容を確かめてから承認する |

### 6.6 配信前の確認事項

- [ ] 差出人と返信先が正しい
- [ ] 配信リストが正しく、宛先は配信に同意した会員だけである
- [ ] 件名と本文に誤りがなく、別の送り手を装う表現がない
- [ ] テスト送信で、表示と配信停止のリンクを確かめた
- [ ] 承認を得ている
- [ ] 予約するなら、00分を避けた

## 7. 配信中・配信後の見方

### 7.1 配信の状態

| 状態 | 意味 |
|---|---|
| 下書き | 編集できます |
| 承認待ち | 申請済みで、内容は固定されています |
| 承認済み | 開始または予約ができます |
| 予約済み | 指定した日時に開始します |
| 開始待ち | 送信の準備中、または他の配信の終了待ちです |
| 送信中 | 1通ずつ送っています |
| 一時停止中 | 止まっています。理由が表示されます |
| 要確認 | 処理が途中で止まり、管理者の判断が必要です（7.5節） |
| 完了 | すべて送りました |
| 中止 | 中止しました。残りは送りません |

### 7.2 件数の見方

| 表示 | 意味 |
|---|---|
| 送信済み（SES受付） | SESが送信を受け付けた件数。配送できない宛先への送信も含みます |
| 配送 | 受信側のメールサーバーが受け取った件数 |
| 配送遅延 | 受信側が一時的に受け取りを遅らせている件数。SESが自動で再試行します |
| バウンス | 届かなかった件数 |
| 苦情 | 受信者が迷惑メールと報告し、SESに通知された件数。**GmailとiCloudの苦情は通知されないため含まれません** |
| 購読設定の変更 | 会員が配信停止や配信設定を変えた件数（停止以外の変更も含みます） |
| 失敗 | アドレスの不備などで、SESが受け付けなかった件数 |
| 不明 | 通信の問題などで、受け付けられたか分からない件数（7.5節） |

- 件数は10秒ごとに更新されますが、配送やバウンスなどは数分遅れて反映されます。
- **「配送」は、受信トレイに届いたことや、読まれたことを意味しません。** 迷惑メールフォルダーに振り分けられることもあります。受信トレイへの到達は、HT2では確認できません。
- 失敗と不明の宛先は、配信履歴の詳細で一覧できます（閲覧者にはアドレスの一部を伏せて表示します）。

### 7.3 1日の送信上限

受信側に急に大量のメールが届くと、受け取りを制限されることがあります。そのため、組織の1日の送信件数に上限を設け、少ない量から段階的に増やします（初期値の案は1日1,000通）。テスト送信も件数に数えます。

- 上限に達した配信は自動で待機し、**翌日0時5分（日本時間）に条件を確かめ直してから続きを送ります。** 画面に再開予定の時刻が表示されます。
- 条件を満たさなければ、そのまま一時停止します。この場合は管理者が原因を直して再開します。
- 上限の引上げは、配送遅延・バウンス・苦情の状況を確かめたうえで、AWSの管理者が行います。初めての配信や、長く配信を休んだ後も、少ない量から始めます。
- 開始から7日たっても終わらない配信は、古い内容を送り続けないよう自動で中止します。

### 7.4 一時停止・再開・中止

- **一時停止**：送信中の配信を止めます。数秒以内に、まだ送っていない分の送信が止まります。
- **再開**：止めた所から続けます。自分たちで止めた配信は、管理者・配信担当・承認者が再開できます。
- **中止**：残りを送らずに終えます。確認のダイアログが出ます。中止した配信は再開できません。
- 一時停止から7日たった配信は、自動で中止になります。

**すでにSESが受け付けたメールは、一時停止や中止をしても取り消せません。**

#### システムが自動で止めたとき

次のような場合、送信中の配信は自動で一時停止し、管理者に通知されます。**再開できるのは管理者だけです。** 管理者は原因を確かめて直し、テスト送信で受信を確かめてから再開してください。原因が直るまで1日の送信上限は上げません。

| 止まる理由（例） | 意味 |
|---|---|
| バウンス率・苦情率の警報 | 組織全体の評判の数値が、しきい値を超えた |
| 配信のバウンス率・配送遅延率 | この配信で、届かない・遅れる宛先の割合が高い。受信側が受け取りを制限している兆候です |
| 配送の記録が届かない | 送ったのに配送やバウンスの記録が届かない。記録の仕組みの故障を疑います |
| 送信元の認証の異常 | DNSの設定が変わったなどで、送信元ドメインの認証が確かめられない |
| SESの停止・応答の不安定 | SESが送信を止めた、または結果の分からない応答が続いた |
| SESの24時間の送信枠 | SESの送信枠を使い切った。枠は直近24時間の合計なので、日付が変わっても戻りません |

### 7.5 結果が分からない宛先と「要確認」

- **結果が「不明」の宛先には、自動で送り直しません。** 二重に届くことを避けるためです。
- 処理が途中で異常終了すると、配信は「要確認」になり、最大20件の宛先について送ったかどうかが分からなくなります。管理者が配送の記録を確かめたうえで、次のどれかを選びます。

| 選択 | 結果 |
|---|---|
| 飛ばして再開 | 該当の宛先に届かない可能性があります（最大20件） |
| 送り直して再開 | 該当の宛先に二重に届く可能性があります（最大20件） |
| 中止 | 残りは送りません |

## 8. 会員からの配信停止

- 会員は、メールソフトの「登録解除」ボタン（ワンクリック解除）か、本文末尾の配信停止URLから手続きできます。手続きはSESが受け付け、以後その会員には送られません。
- 配信停止URLのページでは、配信リストごとの停止と、すべての停止を選べます。このページは英語で表示される場合があるため、フッターに日本語の案内を入れています。
- 「登録解除」ボタンを表示するかどうかは、受信側のメールソフトが決めます。表示されない場合も、本文のURLから停止できます。
- 届かなかったアドレス（宛先不明など）と、迷惑メールとして報告された宛先は、SESが自動で「配送しない宛先」（抑止リスト）に登録します。抑止を解除できるのは、会員から受け取れるようになったと連絡があった場合などに限り、AWSの管理者がSESの画面で行います。
- 停止した会員を、運営スタッフが購読に戻すことはできません。会員が改めて希望した場合だけ、管理者が新しい同意の証跡を付けて再開します（5.4節）。

## 9. 安全に利用するためのお願い

HT2は、会員の意思に沿ったメール配信のためのシステムです。

- 配信に同意した会員にだけ送ってください。購入した名簿や、入手元の分からないアドレス一覧、長く使っていない名簿は使わないでください。
- 差出人名や件名で、他の組織や人を装わないでください。
- 短縮URLや、組織と関係のないリンクは使わないでください。
- 会員が配信停止を希望したら、その意思を尊重してください。
- 会員のアドレスの一覧を、通常のメールやチャットで送ったり、必要以上に保管したりしないでください。
- フィッシング、詐欺、なりすまし、マルウェアの配布などには使わないでください。

特定電子メール法に従い、すべての配信の本文末尾に、送信者の名称・所在地・問い合わせ先と配信停止の方法を自動で表示します。同意の日時と取得経路も宛先ごとに記録します。表示する内容や同意の記録の扱いは、運用開始前に法務確認を行います。

## 10. よくある質問

**Q. Gmail以外のアドレスにも送れますか？**  
A. 送れます。メール事業者の制限はありません。Gmail、Yahoo!メール、Outlook.com、iCloud、携帯キャリアメール、プロバイダメールなどに送れます。

**Q. 自分のAmazonアカウントやGoogleアカウントでログインできますか？**  
A. できません。管理者から発行されたアカウントに、パスワードと認証アプリの二要素認証でログインします。

**Q. `myname@gmail.com` を差出人にできますか？**  
A. できません。差出人は、配信組織が管理する独自ドメインのアドレスに限ります。

**Q. 1日に何通まで送れますか？**  
A. 組織の1日の送信上限と、SESの送信枠の両方の範囲内です。1日の上限は少ない量（案：1,000通）から始め、受信側の状況を見ながらAWSの管理者が引き上げます。送信の速さは既定で毎秒10通で、1万件なら約17分です。1回の配信は最大10万件です。

**Q. CSVに書いた人には、必ず全員に届きますか？**  
A. いいえ。登録済みのアドレス、削除済みのアドレス、形式に問題のあるアドレスは取り込まれません。また、配信停止した会員や、届かないとSESに登録された宛先には送られません。

**Q. 配信を始めた後に、本文を直せますか？**  
A. 直せません。承認された内容は固定されます。未送信分を止めたい場合は中止し、新しい配信を作り直してください。

**Q. 「配送」と表示されたら、受信トレイに届いたということですか？**  
A. いいえ。受信側のサーバーが受け取ったという意味です。迷惑メールフォルダーへの振り分けや、読まれたかどうかは分かりません。

**Q. 配信を停止したはずの会員に届いたと言われました。**  
A. 停止の手続きより前に、そのメールの送信が始まっていた可能性があります。宛先画面で購読状態を確かめ、必要なら管理者に配送の記録の確認を依頼してください。SESが受け付けた後のメールは取り消せません。

**Q. 携帯キャリアのアドレスに届かないと言われました。**  
A. 受信側の迷惑メール設定で、送信元のドメインからの受信が拒否されている場合があります。会員に、送信元ドメインからのメールを受け取れるよう受信設定の見直しをお願いしてください。宛先画面で、そのアドレスが配送しない宛先（抑止）になっていないかも確かめてください。

**Q. HTMLメールや添付ファイルは送れますか？**  
A. 送れません。テキストメールだけです。

**Q. 過去の配信はいつまで見られますか？**  
A. 配信の記録は1年間残ります。1年を過ぎると件名と本文は消え、件数だけが残ります（期間は案です）。

**Q. 配信トラブルが起きたらどうすればいいですか？**  
A. 必要なら配信を一時停止し、配信履歴に表示される配信ID、発生した時刻、画面に出た理由（6.5節の表の表示など）を控えて、組織の管理者に連絡してください。会員のアドレスの一覧をメールなどで送ることは避けてください。

## 11. 正式な運用開始までに決める項目

以下は**まだ確定していません**。運用開始前にこの案内を更新します。

- 運営画面のURLと、組織内の問い合わせ窓口
- 1日の送信上限の初期値と増やし方、自動停止のしきい値
- 法定表示の内容、同意の記録の扱い、削除請求への対応（法務確認）
- 記録の保持期間
- 画面の正式な名称と表示の文言
